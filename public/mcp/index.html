MCP 2026-07-28 — 세션을 버린 프로토콜

MCP(Model Context Protocol) 스펙이 2026-07-28 개정판으로 정식 릴리스됐다. 메인테이너 스스로 "출시 이후 최대 개정"이라 부르는 판갈이로, 핵심은 하나다 — 양방향 상태(stateful) 프로토콜에서 무상태(stateless) request/response 프로토콜로의 전환. 핸드셰이크와 세션이 사라졌고, 서버발 요청·알림·인증·확장 구조가 전부 그 위에서 다시 짜였다.

02 무상태 코어 — 요청이 스스로를 설명한다

이번 개정의 심장. initialize 핸드셰이크와 프로토콜 세션이 사라지고, 모든 요청이 자기 기술(self-describing)이 됐다. 프로토콜 버전·클라이언트 능력·클라이언트 정보가 요청의 _meta에 실려 다닌다.

POST /mcp HTTP/1.1 MCP-Protocol-Version: 2026-07-28 Mcp-Method: tools/call Mcp-Name: search {"jsonrpc":"2.0","id":1,"method":"tools/call", "params":{"name":"search","arguments":{"q":"..."}, "_meta":{"io.modelcontextprotocol/clientInfo":{"name":"my-app","version":"1.0"}}}}
  • 어느 요청이든 어느 인스턴스에나 떨어질 수 있다. 공유 저장소나 sticky session 없이 라운드로빈 로드밸런서 뒤에서 수평 확장. 이게 이번 개정의 존재 이유다.
  • server/discover는 서버 필수, 클라이언트 선택. 능력을 미리 알고 싶은 클라이언트만 호출한다. STDIO에서는 구버전 호환 탐지용으로도 쓴다. 버전 불일치는 UnsupportedProtocolVersionError.
  • 상태는 사라진 게 아니라 자리를 옮겼다. 스펙 권고: 호출 간 상태가 필요하면 툴이 명시적 핸들을 발급하고 모델이 인자로 되넘기게 하라. 전송 계층에 숨은 세션보다 이게 낫다 — 모델이 상태를 "볼 수 있어야" 툴 사이에 이어 쓸 수 있기 때문이다.
  • 같이 제거된 것들 — ping, logging/setLevel, notifications/roots/list_changed. 로그 레벨은 요청별 _meta의 io.modelcontextprotocol/logLevel로 지정하며, 이 필드가 없는 요청에 서버가 로그 알림을 보내는 것은 금지다.

03 MRTR — 서버발 요청의 재설계

툴 실행 중에 사용자 확인이나 추가 입력이 필요할 때, 기존에는 서버가 클라이언트로 역방향 요청(elicitation/create 등)을 보냈다 — 상시 열린 양방향 스트림이 전제였다. 무상태 코어에서는 불가능하므로 Multi Round-Trip Requests 패턴으로 바뀌었다.

  • 흐름: 서버가 resultType:"input_required" + 필요한 질문 목록(inputRequests)을 응답으로 돌려준다 → 클라이언트가 답(inputResponses)을 붙여 원래 요청을 재시도한다.
  • 모든 결과에 resultType 필드가 필수가 됐다("complete" / "input_required"). 구버전 서버가 필드를 생략하면 클라이언트는 "complete"로 간주해야 한다.
  • 재시도 간 상관관계는 서버 몫. 2025-11-25에서 도입됐던 elicitation 완료 알림·elicitationId는 한 버전 만에 제거됐다. 서버는 필요하면 requestState에 자체 식별자를 넣어 추적한다.
  • 실전 의미: "프로젝트 생성 전 비용 확인", "데이터 삭제 쿼리 승인" 같은 실행 중 확인 UX를 무상태 서버에서도 구현할 수 있다. 기존에 stateless로 운영하느라 elicitation을 포기했던 서버들이 이 패턴의 1차 수혜자다.
스트림 복구도 사라졌다 — SSE Last-Event-ID 재개·메시지 재전송이 제거됐다. 응답 스트림이 끊기면 진행 중이던 요청은 유실이고, 클라이언트는 새 요청 ID로 재발행해야 한다. 재시도 로직을 "재개"가 아니라 "재실행" 전제로 다시 볼 것.

04 알림과 구독 — 스트림 하나로 통합

  • subscriptions/listen 단일 스트림. 기존 HTTP GET 엔드포인트와 resources/subscribe/unsubscribe를 대체한다. 클라이언트가 원하는 알림 타입(toolsListChanged·promptsListChanged·resourcesListChanged·resourceSubscriptions)에 명시적으로 opt-in하고, 서버는 subscriptionId로 태깅해 내려보낸다.
  • 요청 스코프 알림은 그대로 요청 응답 스트림에. notifications/progress·notifications/message는 해당 요청의 응답 스트림으로 흐른다 — 구독 스트림과 섞이지 않는다.
  • 관측성 표준화. OpenTelemetry 트레이스 컨텍스트(traceparent·tracestate·baggage)를 _meta로 전파하는 규약이 문서화됐다. 게이트웨이 추적을 자체 규약으로 만들었다면 이쪽으로 수렴시킬 것.

05 캐싱과 라우팅 — 게이트웨이 친화 설계

  • 목록 응답이 캐시 가능해졌다. tools/list·prompts/list·resources/list·resources/read·resources/templates/list 응답에 ttlMs(신선도 힌트)와 cacheScope(public=공유 캐시 허용 / private) 필드가 필수다.
  • 툴 목록은 결정적 순서로 반환 권고. 이유가 명시돼 있다 — 클라이언트 캐싱과 LLM 프롬프트 캐시 적중률. 툴 정의는 프롬프트 접두사 맨 앞에 렌더되므로, 순서가 흔들리면 상위 모델 호출의 캐시가 통째로 깨진다. 프로토콜이 비용 구조까지 내려와 설계된 드문 사례.
  • Mcp-Method·Mcp-Name 헤더 필수. Streamable HTTP POST는 메서드·툴 이름을 헤더로 실어야 한다. 게이트웨이·레이트리미터·WAF가 JSON 바디를 파싱하지 않고 라우팅·인가·과금할 수 있다. 툴 파라미터에서 커스텀 헤더를 만드는 x-mcp-header도 추가됐다.
  • 스키마 표현력 확장. 툴의 inputSchema/outputSchema가 JSON Schema 2020-12 전체 키워드를 허용하게 풀렸고, $ref 해석 요건과 조합 키워드 리소스 상한이 함께 정의됐다.
  • 에러 코드 정리. 리소스 없음이 -32002→-32602(JSON-RPC 정합), 서버 에러 대역이 분할됐다 — -32000~-32019는 구현 정의, -32020~-32099는 MCP 스펙 예약.

06 인증 — DCR의 퇴장

  • Dynamic Client Registration(RFC 7591) 공식 폐기 예정. 표준 경로는 CIMD(Client ID Metadata Documents)로 이동한다. DCR은 하위 호환으로만 유지.
  • RFC 9207 iss 검증. 인가 서버는 응답에 iss를 포함해야 하고(SHOULD), 클라이언트는 코드 교환 전에 기록된 발급자와 대조 검증해야 한다(MUST) — 인가 서버 혼동(mix-up) 공격 차단.
  • 자격증명은 발급자에 바인딩. 발급자 식별자를 키로 저장하고, 다른 인가 서버에 재사용 금지, 인가 서버가 바뀌면 재등록.
  • 데스크톱·CLI 앱의 고질병 수정. DCR 시 application_type을 지정해 localhost 리다이렉트 거부(redirect_uri 에러) 문제를 해소했다.
  • EMA(Enterprise-Managed Authorization) 확장 stable. 조직이 MCP 서버 인가를 중앙 관리하고, 사용자는 한 번의 로그인으로 연결된 서버 전체에 접근한다. Anthropic·Microsoft·Okta 등이 채택 발표.

08 폐기 목록 — 12개월 카운트다운

공식 수명주기 정책(Active → Deprecated → Removed, 최소 12개월 유예)이 이번에 도입됐고, 첫 폐기 대상이 지정됐다. 전부 아직 동작하지만 신규 구현은 채택하지 말라는 상태다.

09 마이그레이션 체크리스트

서버 구현자

  • initialize·세션 ID 의존 코드 제거, server/discover 구현(필수). 세션에 있던 상태는 툴 발급 핸들로 옮길 것.
  • 목록 응답에 ttlMs·cacheScope 채우기 + 툴 목록 결정적 정렬.
  • elicitation을 쓰고 있다면 MRTR 패턴(input_required 반환)으로 재작성.
  • Roots·Sampling·Logging 사용처는 12개월 안에 권고 경로로 이행.

클라이언트(호스트) 구현자

  • 모든 결과에서 resultType 분기 — input_required면 사용자 입력을 받아 원 요청 재시도.
  • 알림이 필요하면 subscriptions/listen에 타입별 opt-in. 스트림 단절 시 "재개"가 아니라 새 요청 ID로 재실행.
  • OAuth: iss 검증 추가, 자격증명을 발급자 키로 저장, CIMD 지원 준비.

게이트웨이·플랫폼 운영자

  • Mcp-Method·Mcp-Name 헤더 기반 라우팅·인가·미터링으로 전환 — 바디 파싱 제거.
  • MCP 서버를 일반 HTTP 서비스로 취급: sticky session 제거, 라운드로빈 LB, 수평 오토스케일.
  • cacheScope:"public" 응답은 공유 캐시 적용 가능 — 툴 카탈로그 캐싱으로 upstream 프롬프트 캐시 안정화까지 연결.
SDK 준비 상태 — TypeScript·Python·Go·C# 공식 SDK가 스펙 릴리스 당일 신버전을 지원하고, Rust는 베타다. 세션 식별자에 의존하던 코드가 마이그레이션 비용의 대부분이라고 메인테이너가 직접 언급했다.

10 API 벤더 쪽 연결 통로

MCP는 "클라이언트(호스트)↔툴 서버" 계약이고, 모델 API의 툴콜링은 "모델↔클라이언트" 계약이다. 두 계층을 잇는 통로는 벤더별로 이미 제품화돼 있다.
