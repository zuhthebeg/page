HARDWARE NOTE · CLAIM CHECK

“지포스 드라이버가
SSD 수명을 깎는다”

커뮤니티에서 퍼진 “621.14·621.24 드라이버가 SSD 수명 단축을 가속하는 버그, 621.35로 올리거나 롤백하라”는 글을 퀘이사존 기사와 NVIDIA 공식 포럼 공지로 대조했다.

작성·확인: 2026-11-24 · 원 게시물: 2026-11-23 · 문헌 대조 / 직접 설치·측정 없음

판정: 실재하는 보고이고, 공식 핫픽스(621.35)도 나왔다. 다만 “모든 지포스에서 수명이 깎인다”는 아니다.

NVIDIA 공식 포럼 공지는 621.35 핫픽스가 “nvlog.nvlgstg 파일에 백그라운드로 과도한 쓰기가 발생할 수 있음”을 고친다고 적는다. 즉 문제 자체는 인정됐다. 그러나 발생은 일부 시스템이고, “수명 단축”은 쓰기량 보고에서 나온 추정이며 실제 고장 사례는 이번 자료에 없다.

공식 핫픽스 확인일부 시스템만 해당수명 영향은 계산상 추정

1. 게시물의 주장을 나눠 보면

게시물 주장확인한 내용 / 판정
드라이버 621.14, 621.24가 문제보고와 일치. 퀘이사존 기사(해외 보도 번역)는 621.14(11월 4일 공개) 이후부터라고 쓰고, 621.24에서도 이어진다는 사례를 전한다. NVIDIA 포럼에는 “621.24에서 nvtopps 파일에 기가바이트 단위로 계속 기록한다”는 글이 올라와 있다.
SSD 수명을 단축시키는 버그범위 조정 필요. 실제로 SSD에 쓰기가 늘었다는 보고는 있다(보고자 시스템에서 SSD의 SMART 총 쓰기량과 Windows 집계가 일치). 그러나 “수명이 줄었다”는 쓰기량을 내구성 지표(TBW)에 대 본 계산이다. 실제 고장·수명 단축 사례는 이번에 확인하지 못했다.
621.35로 업데이트하면 해결공식 공지는 일치. NVIDIA 직원 공지: 621.35 핫픽스는 621.24 기반이며 “excessive writes to file nvlog.nvlgstg may occur in background”를 고친다. 다만 베타·선택 설치·최소 QA의 핫픽스이고, “가장 안전한 방법은 다음 WHQL 드라이버를 기다리는 것”이라고 공지가 직접 적는다. 업데이트 후에도 같은 파일에 쓰기가 계속되면 다른 원인일 수 있다며 로그 제출을 요청한다.
전 버전으로 롤백하라단점이 있다. 기사는 621.01로의 롤백이 쓰기를 피하는 가장 유력한 임시 대응으로 거론되지만, 621.01에는 일부 RTX 5000 시리즈에서 동영상 재생 중 화면이 멈추는 문제가 있고 621.14·621.24에 추가된 최신 게임 최적화도 빠진다고 전한다.
(후속 댓글) 업데이트 잔여 파일 97GB가 쌓여 있었음별개 사례. 한 사용자의 PC에서 NVIDIA 앱의 ota-artifacts\grd 폴더에 잔여 파일이 쌓였다는 경험담이다. 이번에 공식 확인은 하지 못했다. 위 SSD 쓰기 문제와는 다른 이야기다.

2. 숫자를 어떻게 읽나

  • 5분 유휴 기준: 기사에 따르면 621.14에서 515MB, 같은 조건의 621.01에서 2MB 미만이다. 시간당으로 환산하면 약 6GB 대 0.02GB다. 큰 차이는 맞다.
  • “시간당 약 30GB”: 621.24에서 일부 사용자가 보고한 상한 쪽 사례다. 모든 사용자의 값이 아니며 위 5분 값(시간당 약 6GB)과도 다르다. 시스템에 따라 폭이 크다.
  • 수명 계산: 기사는 1TB급 주류 NVMe의 TBW를 약 600TB로 보고, 30GB/시간을 하루 8시간 이어가면 약 7년, 24시간 이어가면 약 2년 3개월이라고 계산한다. 직접 검산하니 600,000GB ÷ 30GB/시간 = 20,000시간이고, 이는 24시간 기준 약 2.28년, 8시간 기준 약 6.8년으로 맞다. 단 상한 사례를 계속 유지한다는 가정이다.
  • TBW는 보증 지표다. 제품별로 값이 다르고, 보증 한도에 닿는다고 곧바로 고장 나는 것도 아니다. 이 페이지는 개별 SSD의 수명을 예측하지 않는다.
  • 발생 조건: 기사는 621.24를 쓰는데 이상이 없는 사례도 여러 건 있어 모든 시스템의 문제는 아니라고 쓴다. NVIDIA 앱 기본 설치 환경에서 브라우저만 열어도 발생했다는 보고가 있다.

3. 해당되는지 확인하고, 해결하는 법

  • 확인: Windows 리소스 모니터의 ‘디스크’ 탭에서 쓰기가 많은 순으로 정렬해, NVDisplay.Container.exe가 C:\ProgramData\NVIDIA Corporation\nvtopps\nct\nvlog.nvlgstg에 초당 수MB씩 쓰고 있는지 본다(기사 설명).
  • 임시 대응(기사): NVIDIA Display Container LS 서비스를 중지하고 그 파일을 삭제한 뒤 서비스를 다시 시작하면 쓰기량이 약 90% 줄지만, 파일이 다시 커지면 원래대로 돌아온다. 근본 해결이 아니다.
  • 공식 수정: 621.35 핫픽스. 공식 포럼 공지의 링크에서만 받는다. 베타이고 최소 QA라는 공지의 경고를 감안해 선택한다.
  • 해당 안 되면: 이미 문제가 없는 사용자가 급히 바꿀 이유는 이번 자료에서 확인하지 못했다. 업데이트를 미룬 사용자가 많다는 댓글이 있지만, 그 버전에서 이 문제가 없다는 근거는 아니다(해당 버전 대역을 이번에 조사하지 않았다).
