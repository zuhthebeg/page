NVIDIA가 일부러 막은
GPU 속도, 풀렸다?

X에서 23만 뷰가 나온 글이다. “NVIDIA가 소비자용 GPU를 일부러 막아뒀는데 누가 풀었다. RTX 3060 +87%, 3090 +65%, 4090 거의 2배. BIOS 플래시도 드라이버 패치도 없다.” 캡처 속 저장소는 Zagitta/gpu-unlock이다. 우리는 이 계열을 이미 두 번 다뤘다(4090판, 윈도우판). 이번엔 RTX 20·30·40을 한 번에 지원하는 원본 v2와 트윗 숫자를 대조했다. 숫자는 원본과 같다. 다만 “2배”는 행렬곱 최대치이고, 실제 체감은 작업마다 0~55%다.

1. “일부러 막았다”는 사실인가

사실이다. 그리고 NVIDIA가 직접 공개한 숫자다. Ada 아키텍처 백서 부록 A의 RTX 4090 사양표를 보면 이렇다.

FP16 곱셈, FP32 누적165.2

출처: NVIDIA Ada GPU Architecture 백서 30쪽. 같은 표의 3090 Ti도 FP16 누적 160, FP32 누적 80으로 절반이다.

AI 학습과 양자화하지 않은 추론은 정확도 때문에 대부분 FP32 누적을 쓴다. 바로 그 모드가 GeForce에서는 절반 속도다. 같은 칩을 쓰는 전문가용 카드는 전체 속도로 돈다. 저장소 FAQ도 이유를 시장 구분이라고 설명한다. 비싼 전문가용 카드를 사게 하려는 것이다. 그래서 트윗의 “일부러”는 과장이 아니다.

2. 트윗 숫자는 어디서 왔나

README의 행렬곱 표 그대로다. 기본 전력 제한, BF16, FP32 누적 조건이다.

단위 TFLOPS. README는 이 수치가 사용자들이 올린 호환성 보고에서 나왔다고 밝힌다. 독립 매체의 통제된 측정은 아니다.

4090의 “거의 2배”는 README 스스로 단서를 달았다. “4090은 텐서 코어보다 전력이 먼저 바닥난다. 기본 전력에서 큰 행렬곱은 최대치보다 훨씬 덜 오른다.” 2배는 이론상 최대 연산 속도이고, 실측 행렬곱이 2배라는 뜻이 아니다. 우리 윈도우판 페이지에서도 실제 행렬곱 개선은 +5%~+90%로 들쭉날쭉했다.

3. 실제로 체감하는 건 얼마나

README의 실제 작업 표가 트윗보다 훨씬 중요하다.

빨라지는 것

LLM 프롬프트 처리(프리필) +25~55%, 첫 토큰까지 시간 25~30% 단축. BF16 LoRA·파인튜닝 +25~50%. SDXL·SD1.5 등 이미지 생성 +30~55%. Wan 2.2 영상 +15~20%. FlashAttention 커널 +50~60%.

그대로인 것

LLM 토큰 생성은 메모리 대역폭이 병목이라 변화 없음. llama.cpp·Ollama 양자화 GGUF는 0~15%(주로 긴 문맥). INT8·FP8·INT4 모델, 게임, FP32 CUDA도 변화 없음.

한 줄 요약 — 이미지 생성하고 학습 돌리는 사람에겐 체감이 크다. Ollama로 양자화 모델 채팅만 하는 사람에겐 거의 차이가 없다. 게임 성능은 그대로다.

4. “BIOS 플래시도 드라이버 패치도 없다” — 맞지만 조건이 붙는다

  • 리눅스 커널 모듈이다. 부팅 초기에 NVIDIA 드라이버보다 먼저 올라가서 속도 선택 레지스터를 바꾸고 카드를 재설정한다. 그다음 순정 드라이버가 붙는다. VBIOS나 드라이버 파일은 안 건드린다는 설명은 맞다. 대신 커널 부팅 옵션을 고치고 initramfs에 모듈을 넣어야 한다.
  • 리눅스 전용이다. 개발자는 윈도우를 유지보수하지 않는다. 비공식 포트(impacifist/Windows-GPU-UNLOCK)를 소개하면서도 “떠도는 윈도우 설치파일은 매우 조심하라”고 경고한다. 코인·웹사이트·설치파일은 전부 이 프로젝트와 무관하다고 못 박았다. 바이럴이 붙으면 가짜 설치파일이 따라붙기 마련이다.
  • 지원 범위가 고르지 않다. RTX 30은 “안정, 사용자 보고 100건 이상”이다. RTX 40·20은 “실험”이고, RTX 50은 미지원에 앞으로도 어렵다고 한다. 노트북은 GPU가 절전으로 꺼지면 해제가 조용히 풀린다.
  • 열린 이슈도 있다. 시큐어부트+UKI 구성에서 부팅 멈춤·검은 화면, PCIe 스위치 뒤 3090 5장에서 스위치 전체가 떨어진 사례, “NVIDIA가 계정이나 드라이버를 막을 수 있나”라는 질문이 아직 답 없이 열려 있다. 보증·약관 문제는 확인된 바가 없다.

5. cocy 판단

트윗은 드물게 원본에 충실하다. 절반 제한은 NVIDIA 백서에 적힌 사실이고, 숫자도 README 표와 같다. 과장은 행렬곱 최대치를 “GPU 성능”처럼 보이게 한 것, 그리고 리눅스 전용·실험 단계라는 조건을 뺀 것이다. 리눅스에서 RTX 30으로 이미지 생성이나 파인튜닝을 돌린다면 해볼 가치가 크다. 결과값이 같고 VBIOS도 안 건드린다. 우리 장비(RTX 3080 Ti)는 윈도우 위에서 돌고 WSL도 윈도우 드라이버를 빌려 쓴다. 그래서 원본 커널 모듈은 바로 못 쓴다. 쓰려면 비공식 윈도우 포트나 리눅스 듀얼부트가 필요하다. 윈도우 쪽 위험도는 윈도우판 페이지에 정리해 두었다.
