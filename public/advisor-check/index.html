Tool tip · viral claim check

Sonnet 지휘, Haiku 탐색,
Opus 자문 — 되는 명령어인가

X에서 "Anthropic이 방금 공유한 Claude Code 최고의 트릭"이라며 이런 명령어가 돈다: claude --advisor opus --subagents haiku. Sonnet 5.5가 코드를 쓰고, Haiku 5.5가 파일을 탐색하고, Opus 5.5는 중요한 결정에서만 조언한다는 구성이다. 설정이 한 줄이라 솔깃하다. 그래서 내 로컬 Claude Code와 공식 문서로 줄 단위로 확인했다.

Claude Codeadvisor서브에이전트직접 실행 검증

5/10판정: 아이디어는 공식 기능이고, 명령어의 절반은 존재하지 않는다.
✓ --advisor opus는 공식 CLI 레퍼런스에 있는 실제 플래그 ✓ Sonnet 5.5 본체 + Opus 5.5 advisor 조합은 공식 허용 조합표에 있음 ✗ --subagents haiku는 없는 플래그. 내 CLI에서 unknown option으로 실패 △ "Haiku가 파일 탐색"은 기본 동작이 아님. 내장 Explore는 본체 모델을 따라감 △ "Opus 컨텍스트 절약"은 부정확. advisor는 매 호출마다 전체 대화를 새로 읽음 △ "Anthropic이 방금 공유"는 이 명령어 조합에 대해서는 근거를 못 찾음

그대로 복붙하면 세션이 시작도 안 된다. 다만 목표(Sonnet이 몰고 Haiku가 탐색, Opus가 자문)는 플래그 하나를 환경변수로 바꾸면 만들 수 있다. 감점은 "존재하지 않는 플래그를 공식 팁처럼 포장한 것"과 효과 설명의 과장이다.

1. 직접 실행해서 확인한 것

로컬은 Claude Code 2.1.280이다. 같은 입력으로 진짜 플래그와 가짜 플래그를 대조했다. 세션을 띄우지 않는 서브커맨드(claude auth status)에 붙여서 API 호출 없이 옵션 파싱만 확인했다.

  • claude --subagents haiku auth status → error: unknown option '--subagents' (Did you mean --agents?)
  • 대조군 claude --totally-bogus-flag auth status → 같은 형식의 unknown option 에러. 즉 --subagents는 아무 말이나 넣은 플래그와 같은 취급이다.
  • 실행 파일 문자열 검색. 설치된 claude.exe에서 --subagents 0건, --advisor 4건.
  • 공식 CLI 레퍼런스. 플래그 표 전문에 --subagents는 없고 --advisor <model>은 있다. 설명: 서버 측 advisor 도구를 세션 단위로 켠다, 별칭 fable·opus·sonnet 또는 전체 모델 ID.

같은 문서가 "--advisor는 claude --help에 나오지 않는다"고 밝히고 있고, 내 로컬 --help에도 실제로 안 나온다. 도움말에 없다고 가짜라고 단정하면 안 되는 이유다. 그래서 도움말이 아니라 파싱 결과와 바이너리로 판단했다.

2. 트윗 문구를 걸러서 읽기

트윗의 주장확인한 것판정
"Anthropic이 방금 공유한 트릭"advisor 기능과 "advisor strategy"는 Anthropic 공식(블로그와 문서). 하지만 이 명령어 조합을 Anthropic이 내놓은 출처는 찾지 못했다부분
--advisor opus공식 플래그. Sonnet 5.5 본체에는 Opus 5 이상 advisor를 허용사실
--subagents haiku플래그 없음. 문서·바이너리·실행 모두 부재거짓
"Haiku가 파일과 문서를 병렬 탐색"내장 Explore 서브에이전트의 모델은 기본적으로 본체 모델. Haiku로 돌리려면 별도 설정이 필요기본 아님
"Opus는 필요할 때만 개입"호출 시점은 모델이 정한다. 문서도 "규칙 기반이 아니다", 횟수 상한·강제 설정은 없다고 명시경향일 뿐
"Opus 컨텍스트를 아낀다"advisor는 호출마다 전체 대화를 받고, 그 읽기는 캐시되지 않는다. 줄어드는 건 Opus로 돌리는 턴 수이고, 대신 advisor 토큰이 Opus 요금으로 별도 청구된다표현 부정확

3. 같은 구성을 실제로 만드는 법

공식 문서 기준으로 맞게 쓰면 이렇다. 아래는 문서의 서술이고, 이 조합을 내가 세션으로 돌려 비용을 재본 것은 아니다.

  • Sonnet 5.5 본체 + Opus advisor. claude --model sonnet --advisor opus. 설정 파일의 advisorModel이나 세션 중 /advisor opus로도 된다. sonnet·opus·haiku 별칭은 Anthropic API에서 각각 Sonnet 5.5·Opus 5.5·Haiku 5.5로 풀린다.
  • 서브에이전트를 Haiku로. 환경변수 CLAUDE_CODE_SUBAGENT_MODEL=haiku. 단 이건 기본값일 뿐이라 서브에이전트 정의의 model 필드나 호출별 지정이 우선한다. 내장 Explore·Plan까지 Haiku로 몰려면 CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1도 같이 필요하다(v2.1.257 이상). 또는 model: haiku를 건 사용자 정의 서브에이전트 Explore를 만들면 내장을 덮어쓴다.
  • 서브에이전트는 advisor를 상속한다. 문서에 "서브에이전트는 설정된 advisor를 상속하고 자기 모델 기준으로 같은 조합 검사를 한다"고 적혀 있다. Haiku 5.5도 Opus advisor를 쓸 수 있는 조합이라, Haiku 서브에이전트가 Opus를 부를 여지가 있다. 얼마나 자주 부르는지는 확인하지 못했다.
쓰기 전 조건 4가지
① 버전. Sonnet 5.5는 v2.1.284 이상, Haiku 5.5는 v2.1.293 이상이 필요하다. 내 로컬은 2.1.280이라 Sonnet 5.5도 못 쓴다. npm 최신은 2.1.295다.
② Anthropic API 전용. Bedrock·Vertex·Foundry에서는 advisor가 없다. LLM 게이트웨이를 끼면 요청이 그대로 전달되는지에 달렸다.
③ 실험 기능. 문서가 "experimental, 동작·가격·가용성이 바뀔 수 있다"고 적었다. DISABLE_TELEMETRY 같은 변수로 피처 플래그 가져오기를 끄면 advisor도 꺼진다.
④ 청구. advisor가 읽는 토큰은 Opus 요금이다. 짧은 작업이면 오히려 Sonnet 단독이 싸다. 문서도 "짧은 작업엔 이득이 적다"고 한다.

4. 효과는 얼마나 되나

이 트릭을 뒷받침하는 공식 숫자는 있지만 세대가 다르다. Anthropic의 advisor strategy 글(API 베타)에 실린 수치는 전부 Sonnet 4.6·Opus 4.6·Haiku 4.5 기준이다.

  • Sonnet + Opus advisor: SWE-bench Multilingual에서 Sonnet 단독 대비 +2.7%p, 작업당 비용 11.9% 감소.
  • Haiku + Opus advisor: BrowseComp 41.2%로, Haiku 단독 19.7%의 두 배 이상. Sonnet 단독에는 점수가 29% 뒤지고 비용은 85% 저렴.

5.5 세대 조합의 공식 수치는 찾지 못했다. 그리고 위 구조는 "작은 모델이 몰고 큰 모델에 묻는" 형태라, 트윗이 말하는 "Haiku가 탐색 서브에이전트"와는 같은 얘기가 아니다. Anthropic 글도 이 방식이 "큰 모델이 쪼개서 작은 워커에게 맡기는 흔한 서브에이전트 패턴을 뒤집은 것"이라고 설명한다.

5. 쓸만한가

쓸 만하다. 단, 트윗 명령어가 아니라 문서대로 구성했을 때다. 긴 리팩터링이나 같은 에러가 반복되는 디버깅처럼 대부분은 단순 턴이고 계획 품질이 결과를 가르는 작업에 맞는다. 반대로 짧은 작업, 매 턴 최상위 모델이 필요한 작업에는 이득이 작다. 결국 비용이 정말 줄어드는지는 내 작업 로그로 재야 한다. Anthropic도 자기 eval 스위트로 단독/조합/Opus 단독 세 가지를 비교해보라고 권한다.

확인하지 못한 것: 실제 advisor 세션의 호출 빈도와 비용, 5.5 세대 조합의 성능 수치, Haiku 서브에이전트가 Opus advisor를 얼마나 부르는지, 트윗이 근거로 삼은 Anthropic 원문 게시물.
