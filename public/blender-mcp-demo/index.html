Claude Code × Blender로
3D 장면을 웹에 띄우기

앞서 검증한 "Opus + Blender + Unreal + Meshy" 레시피 중, 돈이 들지 않는 앞부분만 직접 따라 했다. Claude Code가 Blender MCP로 Blender를 조종해 Poly Haven(CC0) 바위 모델 두 개를 가져오고, GLB로 내보내고, 브라우저의 Three.js로 열었다. 아래 3D 뷰어가 그 결과물이다. 드래그로 돌려볼 수 있다.

Blender 5.2.2 LTSmcp-for-blender 2.1.9Poly Haven · CC0glTF/GLBThree.js

불러오는 중…

결론: 파이프라인은 끝까지 돈다. 다만 "게임에 쓸 만한가"는 아직 모른다.
✓ Claude Code → Blender MCP → Poly Haven 가져오기 → GLB → Three.js 한 바퀴 확인 ✓ 무료 구간만 사용 (Blender 무료, Poly Haven CC0) △ WSL에서 Windows의 Blender로 가는 연결은 그대로는 안 붙어서 구조를 바꿨다 △ AI 3D 생성(generate_3d)·Meshy·Unreal은 쓰지 않았다 ✗ 품질·소요 시간·토큰 비용은 측정하지 않았다

1. 무엇을 했나

  1. 설치. winget으로 Blender 5.2.2 LTS를 깔고 MCP 애드온을 켰다. 애드온은 Blender 안에서 로컬 소켓 서버(127.0.0.1:9876)를 연다.
  2. 연결. claude mcp add로 mcp-for-blender 서버를 등록했다. 노출된 도구는 execute_blender_code, search_assets, import_asset, look, generate_3d, get_scene_info 등 9개다.
  3. 장면 만들기. 기본 큐브를 지우고, Poly Haven에서 boulder_01(바위)과 rock_face_02(암벽)를 1k 텍스처로 가져왔다. 하늘 HDRI(kloofendal_48d_partly_cloudy_puresky)도 월드 조명으로 걸었다. 바위는 암벽 옆으로 옮겼다.
  4. 내보내기. 두 메시를 선택해 GLB로 뽑았다. 처음엔 17.5MB였다.
  5. 웹 용량 줄이기. Blender를 헤드리스로 돌려 Draco 메시 압축과 WebP 텍스처로 다시 내보냈다. 17.5MB → 1.9MB. 이 페이지가 올리는 파일이 그 1.9MB짜리다.
  6. 확인. 헤드리스 Edge에서 Three.js로 열어 메시 2개·삼각형 95,688개로 로드되는 것과 텍스처가 붙은 렌더를 화면으로 봤다.

2. 막힌 지점 두 개

WSL ↔ Windows 소켓Claude Code는 WSL에, Blender는 Windows에 있다. WSL이 NAT 모드라 WSL에서 Windows의 127.0.0.1에 닿지 않는다. 이 애드온은 임의 Python을 실행할 수 있어서 소켓을 바깥에 열지 않는 쪽을 골랐다. MCP 서버를 Windows 쪽 Python에 설치하고 Claude Code가 WSL 인터롭으로 그 실행 파일을 직접 띄우게 했다. 소켓은 끝까지 로컬에만 열려 있다.
target_size가 안 먹는다import_asset의 크기 지정은 Poly Haven 모델에서는 무시되고 실제 크기로 들어왔다. 크기 조정이 필요하면 execute_blender_code로 직접 스케일해야 한다.

한 가지 더. 세션 도중에 등록한 MCP 도구는 그 세션에 올라오지 않는다. 이번엔 새 세션을 열지 않고 JSON-RPC로 같은 서버를 직접 호출해 검증했다.

3. 안전 설정

  • 애드온은 기본값에서 AI가 Blender 안의 임의 Python 코드를 실행할 수 있다. BLENDER_MCP_SAFE_MODE=1로 위험한 스크립트를 걸러내게 했다.
  • 텔레메트리는 disable_telemetry로 껐다. 도구 이름·성공 여부·소요 시간 같은 최소 사용량 집계는 남는다고 안내한다.
  • 작업이 끝나면 Blender를 닫는다. 켜 둔 동안만 소켓이 열린다.

4. 확인하지 못한 것

  • 이 바위들이 우리 게임 분위기에 맞는 품질인지. 렌더는 기본 조명이고 게임 엔진 안에서 돌려보지 않았다.
  • 걸린 시간과 토큰·한도 소모. 재지 않았다. 앞선 검증 글의 "4시간·주간 19%"를 이 실험으로 확인하거나 반박할 수는 없다.
  • generate_3d(AI 생성)와 Meshy MCP. Meshy API 키는 유료 플랜이 필요하다는 점은 앞선 글에서 확인했고, 결제 없이는 해볼 수 없어서 건드리지 않았다.
  • Unreal 5.8 MCP. 설치하지 않았다. 이 PC의 C: 드라이브 여유가 약 33GB(97% 사용)라 수십 GB짜리 엔진은 먼저 공간을 확보해야 한다.
  • Poly Haven의 CC0 에셋은 상업 이용도 가능하다고 사이트가 밝히지만, 이 페이지에서 라이선스 문서를 따로 대조하지는 않았다.

5. 같은 파이프라인으로 3개 더 (sol 6.1에게 시킴)

뷰어 위 탭에서 바꿔볼 수 있다. 작업은 gpt-6.1-sol 워커가 Blender MCP로 하고, 나는 결과물을 직접 열어 확인했다. 수치는 워커가 잰 값이다.

  • 작업장 소품 — Poly Haven 상자·드럼통. 메시 7, 삼각형 46,558, 원본 12.7MB → 819KB. 소요 시간은 기록이 없어 모른다(첫 워커가 중간에 죽음).
  • 작은 숲섬 — 다운로드 없이 코드만으로 만든 저폴리. 메시 45, 삼각형 1,000, 54KB, 67초. 게임 장식 소품으로는 쓸 만하다. 물은 반사·굴절 없는 단색 판이다.
  • 화분 있는 코너 — Poly Haven 탁자·화분·바닥 텍스처 + 코드로 만든 벽·액자·책. 메시 15, 삼각형 72,906, 25.7MB → 921KB, 137초. 데모용으로는 괜찮지만 작은 게임 소품으로는 삼각형이 많다(디시메이션 안 함).

솔직한 한계: 충돌 메시·LOD·모바일 프레임·게임 엔진 안 동작은 확인하지 않았다. 텍스처 노드가 여럿일 때 glTF 샘플러가 첫 노드 설정을 따른다는 내보내기 경고가 두 장면에 있었다. 첫 워커는 PNG를 읽다가 모델 요청이 실패해 죽었고, 재시도 워커에게는 이미지를 열지 말고 수치로만 검증하게 했다.

6. 다음에 해볼 것

무료 구간에서 이어갈 수 있는 쪽은 "저폴리 소품을 Blender에서 만들어 GLB로 뽑고, 웹게임에서 로드해 프레임·용량을 재보는" 단계다. 그 결과가 쓸 만하면 그때 Meshy 유료 플랜이나 Unreal 설치를 판단한다.
