Opus가 5프롬프트로
3D 캐릭터를 움직였다?

X 글은 Opus 5.5가 5개 이하의 프롬프트, 50분 안에 3D 캐릭터를 만들고 애니메이션까지 붙였다고 소개한다. 흐름은 Codex로 컨셉 이미지를 뽑고, Claude에 연결된 Tripo가 3D 모델·텍스처·스켈레톤을 만들고, Claude가 그 스켈레톤용 모션을 만들어 Blender로 내보내는 방식이다. 우리는 이 흐름을 Tripo 공식 개발자 문서로 대조했고, 우리가 만들던 데스나이트 모델에 쓸 수 있는지 따져봤다. Tripo에 우리 모델을 실제로 올려 돌려본 것은 아니다.

공식 문서 기준직접 실행 없음결과물 품질 미검증

판정: 워크플로 자체는 문서로 뒷받침된다. 다만 '5프롬프트·50분'은 작성자의 자기 보고라 검증하지 못했고, 우리 모델이 리깅을 통과할지는 돌려봐야 안다.
✓ 오토리그(Auto Rig) API가 있고 GLB·FBX·OBJ·STL 업로드를 받는다(최대 150MB) ✓ 이식(Retarget) API로 프리셋 모션을 붙인다. 휴머노이드 프리셋에 idle·walk·run·slash·hurt 포함 ✓ 리그 체크(Rig Check)로 리깅 가능 여부를 먼저 물어볼 수 있다 △ '5프롬프트·50분'은 트윗 작성자 보고. 재현 시도 안 함 △ 크레딧 과금과 무료 티어 출력물의 라이선스 범위는 확정하지 못함 ✗ 어느 외부 모델이 리깅을 통과할지, 결과가 게임에서 쓸 만한지는 미검증

1. 트윗 주장 대조

주장확인근거
Tripo가 3D 모델에 스켈레톤을 자동으로 붙인다맞음Auto Rig 문서: 모델에 스켈레톤을 자동 추가. 입력은 이전 생성 작업의 task_id, 업로드한 file_token, 공개 URL 중 하나
Claude가 모션을 만든다부분 확인Tripo 쪽은 프리셋 모션을 이식하는 API를 제공한다. Claude가 직접 키프레임을 쓰는 방식은 문서에 없고, 트윗 원문만 근거다
Blender로 내보낸다맞음출력은 GLB 또는 FBX. Blender는 둘 다 읽는다
5프롬프트 이하, 50분 이내미검증작성자 보고. 우리는 재현하지 않았고, 원 작업의 결과물이 어느 품질인지도 직접 확인하지 못했다
Claude에 연결된 Tripo대체로 맞음Tripo는 공식 CLI(tripo-cli)와 REST API를 낸다. 트윗이 쓴 정확한 연동 방식(MCP 여부 등)은 확인하지 못했다

2. 문서로 확인한 사양

  • 리깅 모델 버전: v1.0(기본값)은 휴머노이드 전용에 90개 이상의 프리셋. v2.5는 네발·여섯발·새·뱀·물고기 등 비휴머노이드용. v3.0은 문서가 휴머노이드에 권장하며, 기본값은 바뀌지 않아 요청에 명시해야 한다.
  • 본 이름 규격: 휴머노이드(biped)일 때 tripo·mixamo·actorcore·unity·unreal·vrm 중 선택. Blender로 넘기거나 엔진 휴머노이드에 붙일 때 이름 규격이 맞으면 후처리가 줄어든다.
  • v2.5·v3.0 휴머노이드 프리셋: idle, walk, run, dive, climb, jump, slash, shoot, hurt, fall, turn. 한 요청에 최대 5개를 묶을 수 있고 제자리 재생(animate_in_place) 옵션이 있다. 데스나이트에는 slash·hurt·idle·walk가 바로 쓸모 있다. 사망 모션이 프리셋에 없다는 점은 직접 만들거나 fall로 대체해야 한다는 뜻이다.
  • 리그 체크: 모델이 리깅 가능한지, 어떤 rig_type이 맞는지 반환한다. 먼저 호출하라고 문서가 권한다.
  • 입력 한계: GLB/FBX/OBJ/STL, 150MB 이하. 가져온 모델은 정규화(크기·위치 보정)되고, 변환 값이 응답에 같이 온다.
범위 한계 — 문서 읽기까지만 했다. 로그인, 크레딧 결제, API 호출, 파일 업로드는 하지 않았다. 가격은 CLI 문서에 적힌 값(오토리그 25크레딧, 모션 이식 1개당 10크레딧, 이미지→3D 20~30크레딧)을 읽은 것이며 실제 청구액은 확인하지 못했다.

3. 우리 데스나이트가 트윗 결과보다 못해 보이는 이유

우리 모델(v6c)은 Blender에서 파이썬 스크립트로 구 타원체·박스·곡선 같은 기본 도형을 쌓아 만든 절차적 모델이다. 객체 275개, 정점 약 3만 2천 개, 리그 없음, 정지 상태다. 게임 카메라에서 66픽셀 정도로 보이는 것이 목표라 윤곽과 실루엣 위주로 다듬었다. 트윗의 결과물과 비교하면 차이가 나는 이유는 아래와 같다고 판단한다.

  • 재질: 우리는 색·거칠기만 있는 단색 재질이다. UV와 베이크된 텍스처가 없다. AI 3D 생성 도구는 보통 붓터치가 들어간 색감 텍스처를 같이 만들어, 같은 형태라도 완성도가 높아 보인다. (이 비교는 우리 추정이며, 트윗 속 모델의 텍스처를 직접 분석하지는 않았다.)
  • 형태: 기본 도형 조합은 면이 매끈하고 대칭적이어서 '조립한 느낌'이 난다. 생성형 모델은 비대칭과 미세한 굴곡이 섞여 있다.
  • 목표 해상도: 66픽셀 목표는 실루엣이 읽히면 충분하다는 기준이라, 디테일을 더 넣어도 화면에서는 차이가 작다. 트윗의 결과는 확대된 렌더 기준이어서 같은 조건의 비교가 아니다.
  • 연출: 컨셉 이미지에서 시작해 조명·포즈까지 맞춘 쇼케이스 렌더와, 정지 시트 컷을 나란히 보면 후자가 불리하다.

4. 우리 모델에 쓸 수 있나

가능성은 있지만 몇 가지 걸린다. 모두 돌려보기 전의 예상이다.

  • 메시 정리: 객체 275개를 하나로 합치고 내보내야 한다. 분리된 도형과 관절 뼈 조각, 불타는 검까지 한 몸으로 합치면 리깅 AI가 팔과 무기를 구분하지 못할 수 있다. 검을 따로 두고 몸통만 리깅하는 편이 안전해 보인다.
  • 체형: 슬림한 몸통에 관절 뼈를 노출한 구조는 사람 형태에 가깝지만, 큰 어깨 장식과 해골 머리 같은 부분이 스킨 가중치를 어떻게 받을지는 모른다. 리그 체크가 첫 관문이다.
  • 텍스처: Tripo의 텍스처 기능을 쓰면 형태는 유지한 채 색감을 얻을 수도 있지만, 현재 아트 방향(검은 판금에 금빛 가시)과 맞을지는 결과를 봐야 한다.
  • 대안: Blender에서 직접 리그를 만드는 방법은 계정·크레딧이 필요 없다. 대신 모션은 우리가 직접 만들어야 한다.
  • 라이선스: Tripo 이용약관은 출력물의 상업적 이용을 허용하는 것으로 읽힌다. 무료 티어에서 만든 출력물의 범위가 다른지는 확인하지 못했다. 게임에 넣기 전에 직접 확인해야 한다.

5. cocy 판단

이 워크플로는 새로운 마법이 아니라 생성·리깅·이식 API를 이어붙인 파이프라인이다. 문서상으로는 정상적으로 이어지고, 휴머노이드라면 슬래시·피격·대기·걷기까지 바로 얻는다. 트윗의 속도는 그럴듯하지만 5프롬프트·50분은 검증된 숫자가 아니다. 우리 데스나이트에는 먼저 리그 체크 한 번(무료로 안내되는 항목)과 몸통만 합친 시험용 GLB 하나로 통과 여부를 보는 것이 비용 대비 가장 싼 확인이다. 통과하면 오토리그와 슬래시·피격 이식으로 넘어가고, 실패하면 Blender 직접 리깅으로 간다.
