MODEL NOTE · CLAIM CHECK

Inkling-2-Mini,
“평민 핵탄”이 맞을까?

한 X 게시물은 Thinking Machines Lab의 Inkling-2-Mini를 “24시간 23만 다운로드, 24층이 48층 두뇌, 26B가 5.4B 비용, 16GB 단일 카드”로 소개한다. 모델 카드·Hugging Face API·llama.cpp PR로 숫자를 하나씩 대조했다.

작성·확인: 2026-11-22 · 원 게시물: 2026-11-21 · 모델 공개: 2026-11-20(카드 기준) · 문헌·API 검증 / 직접 추론 없음

판정: 실재하는 강한 오픈웨이트 모델. 구조·크기 숫자는 대부분 맞지만, 성능은 벤더 보고이고 “바로 편하게 돌아간다”는 이틀 전까지 사실이 아니었다.

Apache-2.0, 26.2B(활성 3.4B, 루프 포함 유효 5.4B), 1M 컨텍스트, Q4 양자화 약 16.6GB는 1차 출처와 일치한다. 그러나 다운로드 수는 사용자 수가 아니고, 성능 표는 제작사가 직접 낸 비교이며 일부 항목은 Qwen3.8-27B가 앞선다. 제작사 스스로 추론 반복 루프, 도구 사용 시 파괴적 행동, 약한 사실 지식을 한계로 적었다. Unsloth 양자화는 llama.cpp 메인라인에서 11-21 11:10(UTC)까지 깨진 출력을 냈다.

1. 무슨 모델인가

  • 제작사·날짜: Thinking Machines Lab. 모델 카드의 릴리스 날짜는 2026-11-20이고, 원본 저장소는 API상 2026-11-17에 만들어졌다. 게시물의 “방금 공개”와는 며칠 차이가 있다.
  • 라이선스: 카드와 HF 메타데이터 모두 Apache-2.0. 별도의 Acceptable Use Policy 링크가 있으나 내용은 읽지 않았다.
  • 형태: 텍스트·이미지를 받아 텍스트만 출력하는 멀티모달. “원생 멀티모달”은 입력 쪽 이야기다.
  • “594B 대형”: 같은 계열의 Inkling-2-Small. HF API의 safetensors 합계가 594,050,672,720이다. 게시물의 수치와 일치.
  • 창업자 소개(전 OpenAI CTO): 이번 조사에서 1차 출처로 확인하지 않았다.

2. 게시물 주장 대조

게시물 주장확인한 내용 / 판정
24층이 48층 두뇌, 중간 12층을 3번맞음. 카드: 24층 디코더, 중간 12층이 가중치를 공유하며 3번 실행되어 토큰당 48번의 층 적용. 단 “깊이 2배”가 곧 “능력 2배”는 아니다. 제작사도 루프가 지식을 더 저장하게 하지는 않는다고 쓴다.
26B 용량, 5.4B만 사용맞음, 정의 주의. 총 26.2B(블로그 26.4B, safetensors 합 26,388,646,440), 활성 3.4B, 루프당 추가 약 1.0B로 유효 5.4B. “5.4B”는 토큰당 가중치 활성량이며 메모리 사용량이 아니다. 전체 가중치는 올려야 한다.
네이티브 100만 토큰·시각·MCP부분 확인. 컨텍스트 1M 지원은 카드에 명시. 이미지 입력도 확인. 1M에서의 실제 메모리·속도·품질은 이번에 확인하지 못했다. MCP Atlas 점수는 있으나 벤더 보고.
Q4 16GB, 3090/4090 또는 32GB Mac에서 풀 성능수치는 맞고 “풀 성능”은 과장. Unsloth UD-Q4_K_M 파일이 16,610,543,328바이트, IQ4_XS 15.73GB, Q4_K_XL 17.63GB. 원본 체크포인트는 약 20GB(NVFP4+MXFP8). 카드의 공식 지원은 DGX Spark, 32GB 이상 Apple 실리콘이고 “다른 GPU는 32GB 이상 VRAM 권장”이다. 24GB 카드에서 긴 컨텍스트가 도는지는 측정하지 않았다.
24시간에 23만 번 다운로드값은 그럴듯, 해석은 과장. Unsloth GGUF 저장소가 2026-11-20 13:09(UTC) 생성, 현재 다운로드 238,152. 게시 시각까지 약 23.5시간이다. 하지만 게시 시점의 값은 확인할 수 없고, 같은 시간 원본 저장소는 7,944, ggml-org GGUF는 61,987이다. 다운로드 수는 평가상 고유 사용자 수가 아니며 “전 세계 개발자가 집어 갔다”는 근거가 되지 못한다.
LM Studio·Ollama로 바로 로컬 실행시점 의존. 아래 4절 참고.

3. 성능 표는 누구의 숫자인가

제작사 블로그와 카드는 Gemma 4 31B, Muse Glimmer, Qwen3.8-27B, Nemotron 3.5 Super VL과 비교한다. 이 표는 제작사가 구성했고 “평가 설정은 모델마다 다르다”고 스스로 밝힌다. 일부 비교 모델 점수가 0.0%대(예: Gemma 4 31B의 FrontierCode 0.0%)인 항목은 하니스 적합 여부에 따라 달라졌을 수 있어 그대로 일반화하기 어렵다.

읽는 법: 코딩 에이전트 지표에서 같은 크기대 모델보다 앞선다는 제작사 주장은 이 표와 일치한다. 그러나 AA Index는 Qwen3.8-27B와 동률이고, 위 표의 세 항목에서는 Qwen이 앞선다. 블로그도 “일부는 Qwen3.8-27B 뒤”라고 적는다. “같은 급에서 전면 1위”가 아니다.

4. 로컬 실행은 지금 어디까지 되나

  • 메인라인 llama.cpp 문제: Unsloth 모델 폴더의 안내문은 PR 32704가 머지되기 전 메인라인에서 NVFP4 스케일이 잘못 풀려 gibberish가 나온다고 경고한다. 해당 PR은 GitHub API상 2026-11-21 11:10(UTC) 머지됐다. 게시물은 그 약 1.5시간 뒤(12:38 UTC)에 올라왔다. 그 전에 받은 빌드에서는 같은 파일이 깨진 출력을 냈을 것이라는 뜻이다. 빌드 날짜 확인이 필요하다.
  • 커뮤니티 이슈: Unsloth 저장소 토론에 “failed to load model”, “Vulkan blowup (Q8)” 같은 글이 있다. 일부는 해결됐을 수 있다. 이번에 하나씩 추적하지 않았다.
  • Ollama·LM Studio: Ollama 라이브러리에 inkling-2-mini 페이지가 있고, LM Studio 커뮤니티 GGUF 저장소가 존재한다. 반면 Ollama 이슈 트래커에는 “GGUF 지원을 위한 llama.cpp 버전 업”, MLX 경로의 프리픽스 캐시 문제 등이 열린 상태로 올라 있다. 실제로 매끄럽게 돌아가는지는 직접 실행하지 않았다.
  • 속도 주장: 제작사의 속도는 614GB/s에서 BF16 가중치, 배치 1을 가정한 이론 상한이다. 실측 토큰 속도가 아니다.

5. 제작사가 적은 한계

  • 지식·사실성: Inkling-2-Small보다 대부분 평가에서 약하고, 사실 회상에서 격차가 가장 크다. 틀린 정보를 자신 있게 말할 가능성이 더 높다.
  • 반복 추론: 코드 디버깅 등에서 긴 추론 루프에 갇히거나 같은 확인을 반복했다. 출력 토큰·에이전트 턴 제한을 권고한다.
  • 에이전트 신뢰성: 세부 지시·프로젝트 관례를 큰 모델보다 덜 지키고, 확인 없이 파일을 지우거나 덮어쓸 수 있다.

그래서 “에이전트 소형 대포”는 검색·도구로 지식을 보완하고, 파괴적 작업은 사람이 막는 구성에서 읽어야 한다. 제작사는 지식 부족을 검색·도구 사용으로 메운다고 설명한다(BrowseComp·DeepSearchQA·MCP Atlas에서 강하다는 보고, 마찬가지로 벤더 수치).

6. 쓸 만한가

조건부로 시험할 가치가 있다. 로컬에서 코딩·도구형 에이전트를 돌려 볼 목적이고 32GB급 메모리 장비가 있다면 후보다. 다만 최신 llama.cpp 빌드 또는 Unsloth 안내 빌드로 받고, 출력 길이와 턴 수를 제한하고, 파일 삭제·덮어쓰기는 승인 후에만 허용하자. 한국어 품질·1M 컨텍스트 실제 성능은 이 자료로 알 수 없다. 이 문단은 문헌 기반 평가이며 직접 실행은 하지 않았다.
