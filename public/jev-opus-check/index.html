에이전트 비용 1/5?

X(@Mahaximus_, 2026-09-28)의 데모 영상이다. 같은 에이전트, 같은 작업, 같은 60번의 판단을 두 방식으로 돌렸다. 모든 판단을 Opus 5.5가 하면 $2.24·3분 37초, 작은 판단은 Jev가 하고 Opus는 진짜 추론에만 쓰면 $0.43·1분 15초. "60번 중 57번은 Opus를 안 거쳤고, 결과물은 똑같다." 공식 가격표와 제3자 벤치마크로 검산했다. 우리 PC에서 로컬 Jev 클론도 새로 돌려봤다.

데모의 계산은 정직하다. 문제는 전제다. "작은 판단"은 쉬운 판단일 때만 Jev가 맞힌다. 게다가 이 절감은 판단 하나하나가 별도 LLM 호출인 구조에서만 나온다. Claude Code나 OpenClaw처럼 모델이 한 턴 안에서 도구를 고르는 에이전트에는 그대로 옮겨지지 않는다.

2. Jev의 판단력은 어디까지 믿을 수 있나

JevBench는 Jev 계열 판단 모델을 82개 시스템으로 비교하는 제3자 오픈 벤치마크다(MIT, v1.4.1, 2026-09-23). 문항 일부는 공개하지 않는 비공개(sealed) 308문항이라, 공개 문항에 맞춰 학습한 효과를 걸러낸다. 이 비공개 문항에서 찍어서 맞힐 확률은 29.3%다.

출처: JevBench v1.4.1 결과 파일. "어려움"은 2~6천 토큰짜리 정책 문서, 함정, 여러 단계 추론, 날짜·숫자 계산 문항이다.

읽는 법: Jev는 도구 선택이나 형식 확인 같은 쉬운·보통 판단은 거의 다 맞힌다. 그런데 처음 보는 어려운 판단에서는 찍기보다 7%p 높은 수준이다. 같은 문항에서 싼 LLM(GPT-6 Luna)은 93~96%를 맞혔고, 1,000번 판단 비용은 $0.127로 Jev의 약 3배였다. "Opus의 1/200"이 아니라 "싼 LLM의 1/3"이 현실적인 비교다. 2026-09-16 Jev 출시 때 TypeSafe 자체 벤치마크에서도 Jev 종합 정확도는 67.8%로, 프론티어 모델의 74.1%보다 낮았다(jev-check).

데모의 세 가지 작은 판단에 대입하면 이렇다. "다음에 어떤 도구를 쓸까"와 "이 출력이면 충분한가"는 대개 쉬운·채점형이라 Jev의 강점 구간이다. "목표를 달성했나"는 다르다. 틀리면 일을 덜 끝낸 채 멈추거나 끝없이 돌기 때문에 오판 비용이 가장 크다. 이 판단만큼은 싼 LLM이나 규칙으로 두는 편이 안전하다(평가).

4B~12B급 로컬 클론은 공개 문항에서 이미 Jev와 비슷한 점수를 낸다. 그리고 비공개 문항에서는 Jev를 포함한 판단 전용 모델 전부가 비슷하게 무너진다. 즉 "로컬로 Jev급"은 이미 현실이다. 다만 그 Jev급이 쉬운 판단까지만이라는 한계도 같이 따라온다.

3-2. 우리 한국어 대화로 직접 재봤다 (RTX 3080 Ti)

OpenClaw 텔레그램에서 실제로 받은 한국어 메시지 147건을 "가벼움·보통·무거움"으로 라벨링하고, 어느 모델에 보낼지 판단시켰다. 직전 대화 2턴을 같이 넣었다. 9/26 실험에 이번에 새로 나온 2B를 추가했다.

범위는 선택지 순서를 뒤집은 두 조건의 값. 라벨러 1명, 147건이라 일반 벤치마크가 아니라 현장 관찰이다. 원문 메시지는 공개하지 않는다. Jev 원본 API는 개인 대화를 외부로 보내야 해서 이 실험에 넣지 않았다. 2B는 최적화 커널 없이 fp32로 돌렸다.

2B는 0.8B보다 확실히 나아졌다(+17%p). 하지만 147건 중 113~126건을 "보통"으로 보내서, 전부 보통으로 보내는 기준선보다 3%p 높은 데 그쳤다. 가벼움은 10건 중 2건만 알아봤다. 사람마다 다른 "이 일은 무겁다"는 기준은 아무 학습 없이 바로 쓰는 판단 모델이 알 수 없다. 이 용도로 쓰려면 우리 라벨로 학습시켜야 한다.

4. OpenClaw·Claude Code에 붙이는 법

먼저 구조부터 짚어야 한다. 데모의 57번 절감은 판단 하나하나가 별도 LLM 호출인 오케스트레이션(LangGraph처럼 코드가 "다음은 뭐 할까"를 매번 모델에 묻는 구조)에서 나온다. Claude Code와 OpenClaw는 다르다. Opus가 한 턴 안에서 생각하며 도구를 고르기 때문에, "다음 도구 선택"이라는 별도 호출 자체가 없다. 떼어낼 게 없으니 절감도 없다. Jev류를 끼울 수 있는 곳은 훅, 곧 에이전트 바깥의 관문뿐이다.

4-1. Claude Code

데모의 판단Claude Code 훅추천 판단자
목표를 달성했나Stop / SubagentStop — ok:false면 이유를 Claude에게 돌려주고 계속 일하게 함Haiku 급 prompt 훅 (Jev는 어려운 판단에서 약함)
이 출력이면 충분한가PostToolUse + continueOnBlock:true로컬 판단 모델 가능 (쉬운 채점형)
이 도구를 실행해도 되나PreToolUse규칙(권한 설정)이 1순위, 모델은 보조
어느 모델로 처리할까하위 에이전트의 model 지정작업 종류별 고정 (우리 실측에선 규칙 > 모델)

settings.json 예시다. Stop 시점에 가벼운 모델이 "요청을 다 끝냈나"만 판정한다(공식 문서의 prompt 훅 형식, model 생략 시 백그라운드용 기본 모델).

{
  "hooks": {
    "Stop": [{ "hooks": [{
      "type": "prompt",
      "model": "claude-haiku-4-5",
      "prompt": "Did the assistant finish every task the user asked for, with tests run? $ARGUMENTS\nReply ok:true, or ok:false with the missing item as reason.",
      "timeout": 30
    }]}]
  }
}

로컬 판단 모델(Ollaya의 /v1/systemone이나 Laya·Jev-Style 서버)을 쓰려면 type: "command" 훅에서 로컬 서버를 호출하고, 막을 때 {"decision":"block","reason":"..."}를 출력하면 된다. 외부로 나가는 데이터가 없고 호출 비용은 0이다.

4-2. OpenClaw

용도OpenClaw 플러그인 훅비고
모델 라우팅before_model_resolve — 세션 시작 전에 provider/model을 결정적으로 덮어씀우리 실측상 규칙 + 직전 모델 유지가 판단 모델보다 나음
도구 차단·승인before_tool_call — block 또는 requireApproval 반환확신도가 낮으면 사람 승인으로 넘기는 용도에 적합
목표 달성 확인before_agent_finalize — 최종 답을 보고 모델에 한 번 더 돌리도록 요청1회 추가 패스라 무한루프 위험 적음
필요 없는 턴 막기before_agent_run — 모델 호출 전에 실행 자체를 차단embedded·CLI 러너만 지원

대화 내용을 읽는 훅은 비번들 플러그인이면 plugins.entries.<id>.hooks.allowConversationAccess=true가 필요하다(OpenClaw 문서). 위 표는 문서 기준 설계안이고, 우리 환경에서 플러그인을 만들어 붙여보지는 않았다.

우리 환경에서 가장 큰 절감 지점(평가): 채팅 한 턴 안의 판단이 아니다. "새 소식 없음"으로 끝나는 정기 자동 작업이다. 매 2시간·매일 도는 점검 잡들이 에이전트를 깨워 한참 돌린 뒤 NO_REPLY로 끝나는 경우가 많다. 에이전트를 부르기 전에 "새로 할 일이 있나?"를 스크립트나 로컬 판단 모델로 먼저 거르면, 아무 일 없는 날의 비용이 거의 0이 된다. 데모가 말한 "Jev가 먼저 묻고, 필요할 때만 Opus"가 가장 깔끔하게 맞아떨어지는 구조가 바로 이것이다.

결론

  • 데모: 계산은 정직하다. 하지만 "결과물 동일"은 한 번의 영상이고, Jev는 어려운 판단에서 찍기 수준이다. 작은 판단의 현실적 대안(싼 LLM)과 비교하면 절감폭은 크게 줄어든다.
  • 로컬 Jev: 이미 쓸 만하다. 4B~12B 클론은 공개 벤치마크에서 Jev와 비슷하고, 2B는 우리 3080 Ti에서 건당 0.24초로 돈다. 쉬운 관문(형식 검사, 출력 채점, 저위험 이진 판단)에는 무료·로컬이라는 장점이 크다.
  • 쓰지 말 곳: 한국어 대화의 난이도 라우팅(규칙이 더 나음)과 "목표 달성" 같은 오판 비용이 큰 판단.
  • 쓸 곳: Claude Code의 PostToolUse 출력 채점, OpenClaw의 before_tool_call 승인 분기, 그리고 무엇보다 자동 작업을 깨우기 전의 "할 일 있나?" 관문.
