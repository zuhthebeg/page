에이전트가 코드를 만질 때 생기는 고질병 — 멋대로 가정하고, 과설계하고, 시키지도 않은 코드를 건드리는 것 — 을 잡는 오픈소스 스킬을 골라 정리했다. 카파시 4원칙(행동 규율), Superpowers(개발 방법론), Understand-Anything(코드베이스 지식그래프), 그리고 에이전트 메모리(세션을 넘는 기억). 각각 무엇이고, 우리 환경에 어떻게 넣었는지까지.

00 왜 이 넷인가

네 스킬은 같은 큰 문제를 서로 다른 층위에서 친다. 카파시는 "매 순간 어떻게 행동할지"의 규율, Superpowers는 "한 기능을 처음부터 끝까지 어떤 절차로 굴릴지"의 방법론, Understand-Anything은 "낯선 코드를 어떻게 파악할지"의 도구, 메모리는 "세션을 넘겨 무엇을 기억할지"다. 하나를 고르는 게 아니라 넷을 포개는 그림이 맞다.

01 카파시 스킬 — 에이전트 행동 4원칙

Andrej Karpathy Skillsgithub · forrestchang/andrej-karpathy-skills

카파시가 트윗으로 정리한 "LLM 코딩 에이전트의 함정"을 단 한 장의 CLAUDE.md로 코드화한 것. 코드를 실행하는 스킬이 아니라 행동 지침이라 공급망 위험이 거의 없다.

"모델은 네 대신 틀린 가정을 하고 확인 없이 달려간다. 혼란을 관리하지 않고, 명확히 묻지 않고, 모순을 드러내지 않고, 트레이드오프를 제시하지 않고, 막아야 할 때 막지 않는다. … 100줄이면 될 걸 1000줄짜리 비대한 구조로 만든다." — Andrej Karpathy

4원칙

  • Think Before Coding — 가정을 말로 꺼내고, 애매하면 묻고, 더 단순한 길이 있으면 반박하고, 헷갈리면 멈춰서 무엇이 불명확한지 짚는다.
  • Simplicity First — 문제를 푸는 최소 코드만. 안 시킨 기능·일회용 추상화·없을 상황 대비 에러처리 금지. 200줄이 50줄로 되면 다시 쓴다(YAGNI).
  • Surgical Changes — 건드려야 할 것만 건드린다. 옆 코드 "개선"·드라이브바이 리팩터 금지. 기존 스타일에 맞춘다. 내 변경이 만든 고아 코드만 치운다.
  • Goal-Driven Execution — 명령형("검증 추가해")을 검증형("틀린 입력 테스트 짜고 통과시켜")으로 바꾼다. 강한 성공기준을 주면 모델이 알아서 루프 돈다.
우리에게: 이 4원칙은 우리가 이미 지키려던 규율(SOUL의 "surgical", 증거 기반 검증, 과설계 경계)과 정확히 같은 결을 가진다. 카파시의 권위로 한 장에 압축돼 있어 — 코덱스/서브에이전트 위임 프롬프트에 그대로 박기 좋다.

02 Superpowers — 에이전트 개발 방법론

Superpowersgithub · obra/superpowers (Jesse Vincent)

"브레인스토밍 → 계획 → 서브에이전트 실행 → 리뷰"를 강제하는 조합형 스킬 묶음 + 부트스트랩 지침. 에이전트가 코드부터 짜지 않고 한 발 물러나 스펙을 캐묻게 만든다. GitHub 트렌딩 1위를 찍은 그 라이브러리.

핵심은 true red/green TDD · YAGNI · DRY를 절차로 박아, "한 번 go 하면 두어 시간 자율로" 굴러가게 하는 것. 스킬이 자동 트리거라 특별히 호출할 필요가 없다.

중요: 이건 우리 환경에 이미 상당수 설치돼 있다. brainstorming, writing-plans, executing-plans, test-driven-development, using-git-worktrees, subagent-driven-development, using-superpowers 등 — 전부 이 Superpowers 계열이다. 즉 "추가"가 아니라 "이미 보유 + 활용도 점검"이 맞는 그림. 공식 마켓플레이스 최신본으로 갱신할지는 선택.

03 Understand-Anything — 코드베이스 지식그래프

Understand-Anythinggithub · Lum1104/Understand-Anything

임의의 코드베이스(또는 마크다운 위키)를 대화형 지식그래프로 바꾼다. 멀티에이전트 파이프라인이 모든 파일·함수·클래스·의존성을 노드로 매핑하고, 노드를 클릭하면 그 목적·의존·아키텍처 맥락을 평문으로 보여준다. "코드를 눈 감고 읽는" 걸 막는 도구.

  • 구조 + 비즈니스 도메인 둘 다 매핑 — 코드가 실제 업무 흐름과 어떻게 연결되는지까지.
  • 결과물은 JSON 한 파일(.understand-anything/knowledge-graph.json) — 한 번 만들면 대시보드는 LLM 호출 없이 독립 구동.
  • 증분 분석 — 바뀐 파일만 재분석해 토큰 절약. .understandignore로 제외 가능.
  • 커맨드: /understand(전체 분석) · /understand-dashboard(시각화) · /understand-chat(맥락 대화).
우리에게: 거대한 단일 index.html 게임들이나 admin/relay 같은 다파일 서비스의 "어디가 담당 코드인지" 파악에 후보. 단, 최초 /understand는 전체 코드를 LLM에 태우므로 토큰 비용이 든다 — 큰 레포에 무턱대고 돌리지 말고 필요한 모듈 위주로. (의미 검색은 기존 Semble과 역할이 겹치니 비교 후 선택.)

04 에이전트 메모리 — 세션을 넘는 기억

에이전트의 고질병 중 하나는 세션이 끝나면 다 잊는 것. 이를 메우는 메모리 스킬은 크게 두 갈래다 — 외부 플러그인을 얹거나, 파일 기반 시스템을 규율로 굴리거나.

옵션방식특징
claude-mem thedotmack플러그인세션 관찰 자동캡처→AI압축→주입. SQLite + 벡터검색. 가장 인기.
recall joseairosaMCP 서버Redis/Valkey 브레인. 셀프호스트 or SaaS.
claude-code-memory LuciferForge마크다운의존성 0, 파일 기반 단순형.
네이티브 memory tool Anthropic플랫폼/memories 디렉토리 CRUD.
우리 선택: 우리는 이미 정교한 파일 기반 메모리 시스템을 갖고 있다 — auto-memory(사실 1개=파일 1개, frontmatter + 인덱스), 일일 노트, 큐레이션된 MEMORY.md, memory_search/get, 드리프트 점검용 memory-harness.js까지. claude-mem 같은 외부 플러그인은 CLAUDE.md를 점유하고 자체 SQLite/벡터 주입을 돌려 우리 시스템과 충돌한다. 그래서 외부 통째 도입이 아니라 — 우리 시스템을 일관되게 쓰는 "메모리 규율" 스킬을 추가했다.

규율 스킬의 골자: 답하기 전 recall(memory_search→get, 추측 금지) · 단일 사실=단일 파일(frontmatter: name/description/type) · 일일 노트(raw) vs MEMORY.md(큐레이션) 분리 · 인덱스 한 줄 유지 · 상대날짜→절대날짜 · 공유 컨텍스트에선 개인 메모리 비로드. 메인뿐 아니라 서브에이전트·위임에도 휴대된다.

05 우리 환경 적용

  • 카파시 4원칙 → 스킬로 추가(항상 참조 가능한 코딩 규율). 위임 프롬프트 계약에 녹임.
  • Superpowers → 이미 보유. 재설치 대신 보유 스킬 점검·활용. 공식 최신본 갱신은 필요 시.
  • Understand-Anything → 도구로 도입하되 설치 스크립트는 그대로 파이프하지 않고 검토 후 반입(공급망 주의). 큰 레포 분석이 필요한 순간에 선택적으로 사용.
  • 에이전트 메모리 → 외부 플러그인 대신 메모리 규율 스킬(agent-memory-discipline)로 추가. 기존 파일 기반 시스템을 충돌 없이 일관 운용.
