2. 왜 "토큰 98% 절약"이 안 되나

DeepGEMM은 행렬곱 같은 GPU 연산을 빠르게 하는 커널이다. 같은 GPU에서 더 빨리 계산하면 그 GPU로 모델을 직접 돌리는 쪽의 토큰당 원가가 내려갈 수 있다. 트윗의 논리("더 빠른 GPU 수학 → GPU당 더 많은 토큰 → 더 싼 토큰")는 여기까지는 맞다.

문제는 대상이다. GPT Astra와 Opus 5.5는 OpenAI와 Anthropic이 자기 서버에서 돌리는 클로즈드 모델이고, 사용자는 회사가 정한 단가로 청구받는다. 사용자가 DeepGEMM을 "꽂을" 곳이 없다. 이 라이브러리로 줄어드는 건 오픈 모델을 자기 GPU에 올린 쪽의 서버 비용이지, API 요금이 아니다.

5. 우리한테 의미 있나

  • API로 GPT·Claude를 쓰는 입장: 바뀌는 게 없다. 청구서를 줄이는 현실적 수단은 프롬프트 캐싱, 모델 라우팅, 작은 모델 폴백이다(평가).
  • 로컬 GPU 입장: 요구 아키텍처가 SM90/SM100(Hopper/Blackwell)이라 RTX 30·40 세대 소비자 GPU에서는 쓸 수 없다. 직접 돌려보진 않았고, README 요구사항 기준의 판단이다.
  • 자체 서빙 팀 입장: MIT 라이선스라 읽고 가져다 쓰기 좋은 레퍼런스 구현이다. 실제 이득은 모델·배치 크기·통신 구성에 따라 달라지므로 자기 환경에서 측정해야 한다.

결론

저장소는 진짜고 DeepSeek의 GPU 최적화 수준을 볼 수 있는 좋은 자료다. 그러나 "남의 API 토큰값을 98% 깎아준다"는 문장은 라이브러리가 하는 일과 맞지 않는다. 숫자도 트윗 안에서 서로 맞지 않는다.
