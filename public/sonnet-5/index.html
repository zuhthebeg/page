Claude Sonnet 5

Claude Sonnet 5(claude-sonnet-5)는 속도와 지능의 균형을 노린 중간 티어로, Sonnet 4.6의 드롭인 후속이다. 스펙보다 일정이 먼저 중요하다 — 도입가 $2/$10은 2026-08-31까지이고, 9월 1일부터 $3/$15로 오른다. 여기에 새 토크나이저(같은 텍스트가 약 30% 더 많은 토큰)가 겹친다.

01 가격 — 두 겹으로 오른다

항목~2026-08-312026-09-01~
입력 / 출력$2 / $10$3 / $15
5분 캐시 쓰기$2.50$3.75
1시간 캐시 쓰기$4$6
캐시 읽기$0.20$0.30
단가만 보면 +50%지만, 실제 체감은 그보다 크다 — Sonnet 5는 새 토크나이저를 쓴다. 같은 입력 텍스트가 Sonnet 4.6 대비 약 30% 더 많은 토큰으로 계산된다(정확한 비율은 콘텐츠에 따라 다름). per-token 단가는 그대로여도 요청당 비용이 달라진다. 4.6에서 잰 토큰 수로 짠 예산은 그대로 쓸 수 없고, count_tokens를 Sonnet 5 기준으로 다시 돌려야 한다.

부수 효과도 있다. 1M 컨텍스트에 들어가는 실제 텍스트 양이 줄고, 4.6에 맞춰 잡아둔 max_tokens가 같은 분량의 출력을 잘라먹을 수 있다. 컨텍스트가 빠듯한 파이프라인일수록 먼저 재측정할 것.

02 Sonnet 4.6에서 깨지는 것 — 두 개

  • 수동 확장사고 제거 — thinking:{type:"enabled", budget_tokens:N}은 400. adaptive + output_config.effort로 대체한다. 토큰 예산과 1:1 대응은 없다
  • 샘플링 파라미터 — temperature·top_p·top_k를 기본값이 아닌 값으로 보내면 400. 값을 지우고 프롬프트로 옮기는 게 안전하다

조용히 바뀐 것 — 에러는 안 나지만 동작이 달라진다.

  • adaptive thinking이 기본 ON. 4.6은 thinking 필드를 생략하면 사고 없이 돌았다. Sonnet 5는 같은 요청이 사고하며 돈다. max_tokens는 사고+응답 합계의 상한이므로 빠듯하게 잡아둔 값은 잘릴 수 있다. 끄려면 thinking:{type:"disabled"}를 명시한다
  • 사고 내용이 기본 비공개. 사고 블록은 오지만 텍스트가 비어 있다. 사용자에게 추론을 스트리밍한다면 display:"summarized"를 명시해야 한다 — 안 그러면 출력 전 긴 정적으로 보인다
  • 사이버보안 안전장치가 Sonnet 티어에 처음 들어갔다. 거부는 에러가 아니라 HTTP 200 + stop_reason:"refusal"로 온다. content[0]을 무조건 읽는 코드는 여기서 깨진다

Sonnet 4.5 이하에서 올라온다면 assistant 프리필 거부와 툴 파라미터 JSON 이스케이프 차이도 함께 걸린다.

03 Opus 5와 뭐가 다른가

둘은 API 표면이 거의 같다 — 사고 기본 ON, effort 기본 high, 1M 컨텍스트, 128k 출력, Priority Tier 미지원, 수동 확장사고·샘플링 파라미터·프리필 모두 400. 다른 건 네 가지고, 전부 게이트웨이 설계에 영향을 준다.

뒤집혀 있어서 헷갈리는 지점 — 보통 상위 모델이 더 많은 걸 지원할 거라 기대하지만, web fetch는 Sonnet 5에만 있고 Opus 5에는 없다. 반대로 대화 중간 role:"system" 메시지는 Opus 5에만 있다. 후자는 단순한 기능 차이가 아니라 비용 차이다 — 대화 도중 지시를 바꿔야 할 때, top-level system을 수정하면 그 앞의 캐시가 전부 무효가 되는데, Opus 5는 messages 배열에 system 메시지를 덧붙여 캐시를 살린 채 지시를 갱신할 수 있다. Sonnet 5에서는 이 방법을 못 쓴다.

04 도입 검토 시 점검 항목

  • 9월 1일 기준으로 비용을 다시 계산해 둘 것. 단가 +50%와 토큰 수 ~30%↑가 곱해진다. 지금 도입가로 잡아둔 예산은 9월에 그대로 쓸 수 없다
  • count_tokens를 Sonnet 5 기준으로 재측정. 4.6에서 잰 값에 배수를 곱해 추정하지 말고 대표 프롬프트로 직접 잰다
  • 사고를 끄고 쓰던 경로를 찾을 것. 4.6에서 thinking을 생략하는 방식으로 "사고 없이" 돌던 코드는 Sonnet 5에서 조용히 사고를 시작한다. 의도한 동작이면 명시적으로 disabled를 넣는다
  • 거부 분기를 먼저 넣는다. HTTP 200에 stop_reason:"refusal"이므로 예외 처리로는 잡히지 않는다
  • 캐시 최소 길이가 1,024 토큰이라 짧은 시스템 프롬프트는 캐싱되지 않는다. 미달이면 에러 없이 조용히 캐싱만 안 되므로, cache_read_input_tokens가 계속 0인지로 확인한다
