Jev 응용 앱 5종,
무엇이 실제로 쓸 만한가

GitTrend의 2026-10-24 X 게시물은 Jev를 얹은 브라우저 에이전트·압축기·코드 검색·트레이더·SQL 확장 다섯 개를 소개했다. 다섯 저장소는 모두 존재한다. 하지만 「7초 비행기 예약」「같은 지능에 비용 30% 절감」「블록마다 매매해 스프레드 수익」을 그대로 실사용 성능으로 읽으면 안 된다.

저장소 실사벤치마크 범위실무 적용

7/10판정: 응용 코드는 진짜다. 일반화된 성능·거래 수익은 아직 아니다.

1. 주장과 검증 범위

원문은 5종을 「초고속 브라우저 에이전트, 세부 내용을 잃지 않는 컨텍스트, 저렴한 코드 검색, 온체인 거래 판단, 자연어 SQL」로 묶는다. 이번 검증은 2026-10-25 GitHub 저장소·README·공개 측정 기록·라이선스를 직접 읽은 문서 검증이다. 우리 환경에서 API 호출·라이브 벤치마크·실거래를 재실행한 결과가 아니다. 아래의 ‘확인’은 코드와 공개 기록의 존재를 뜻하고, 측정값은 별도로 ‘작성자 보고’라 표시한다.

Jev 자체 판단 정확도의 한계는 기본 팩트체크, 에이전트 비용·로컬 비교, 게이트웨이 적용 검토에서 이미 다뤘다. 여기서는 그 모델을 붙인 응용의 증거만 본다.

2. 다섯 저장소 실사

① 브라우저 — browser-use/jev-ultrafast

실체: Jev가 한 요청에서 동작과 대상 요소를 함께 고르고, 입력 텍스트가 필요할 때만 소형 LLM을 호출한다. DOM을 번호 붙인 요소 표로 읽는 실제 에이전트 코드와 기록 스크립트·측정표가 있다. MIT, 2026-09-16 생성, 최근 코드 커밋 09-18, 확인 당시 약 23,609★.

수치: 영상의 7.073초는 취리히→런던 항공편 검색 결과 표시까지다. 예약·결제는 하지 않는다. 최초 페이지 관찰과 사후 독립 검사는 타이머 밖이다. 동일한 한 작업을 교차 3쌍 반복한 중앙값은 기존 9.450초→최적화 7.092초(25% 감소), 양쪽 모두 3/3 성공이었다. 측정 JSON과 스크립트는 확인했으나 수치는 작성자 보고·한 작업 한 프로필 조건부다. 임의 사이트 성공률이나 보편적인 7초를 뜻하지 않는다.

② 컨텍스트 — tamaratran/fast-jev-compaction

실체: Claude Code 플러그인과 npm 라이브러리. Jev로 오래된 도구 호출·결과의 보존 여부를 점수화하고, 불필요한 쌍을 삭제하거나 결과 앞부분만 남긴다. 살아남은 내용은 재서술하지 않는다. MIT, 2026-09-17 생성, 최근 코드 커밋 09-17, 약 7,758★. 단위 테스트는 가짜 Jev를 사용한다.

주의: ‘무손실 압축’은 부정확하다. 보존된 조각이 원문 그대로일 뿐 삭제·절단된 도구 결과는 복구되지 않는다. 모델이 중요한 오래된 결과를 버릴 수 있고, 설정상 Claude Code function hook 조기 접근 기능이 필요하다. 공개된 실사용 정확도·비용 절감 벤치마크는 확인하지 못했다. 따라서 성능은 미검증이다.

③ 코드 검색 — dzhng/jevgrep

실체: 자연어 질문으로 관련 코드·원문 조각을 찾는 CLI. MIT, 2026-09-26 생성, 최근 코드 커밋 10-21, 약 2,893★. 과제별 평가표와 기계 판독 기록을 공개했다.

수치: 작성자 실험에서 조정된 Python SWE-bench 10문제의 해결 수는 양쪽 모두 8/10. 홍보 그림의 ‘약 30%’는 코딩 모델 Sol 비용 $7.62→$5.44의 28.6%로 Jev 비용 제외다. Jev를 포함한 0.4.3 재실행은 $7.622→$5.656, 25.8% 절감이며 Jev 부분은 토큰 사용량×공개 단가의 추정치다. 같은 8/10이라도 작은 표본·기준선 재사용·과제별 변동이 커 ‘동일한 지능’이나 일반적 30% 절감으로 확장할 수 없다. 작성자 보고·조건부.

④ 거래 실험 — jarrodwatts/jev-trader

실체: Monad Kuru MON-USDC 오더북을 읽고 매 블록 매수/매도 방향을 정해 post-only 지정가 주문을 내는 실험 코드. MIT, 2026-09-16 생성, 최근 코드 커밋 10-13, 약 3,074★. 기본 MODEL=mock는 모멘텀 휴리스틱이며, PRIVATE_KEY 없으면 dry-run이다. 배포 대시보드도 mock·dry-run이라고 명시한다.

주의: ~300ms는 블록 주기·목표 예산이지 Jev 실전 왕복이 그 안에 끝났다는 증거가 아니다. README의 루프 중앙값 100ms도 mock 모델 dry-run 측정이다. 실제 수익률·실거래 Jev의 체결률은 미검증. 메이커 주문은 체결 보장도 스프레드 이익 보장도 아니며 가스·재고·가격 역행 위험이 있다. 자금 투입의 근거로 쓰지 않는다.

⑤ SQL 확장 — realZachi/pg-jev

실체: WHERE jev(row, '조건')처럼 자연어 조건으로 행을 분류하고 jev_prob()로 확률을 받는 PostgreSQL 확장. 라이선스 파일은 PostgreSQL License(GitHub API 표기는 ‘Other’), 2026-09-17 생성, 최근 코드 커밋 10-06, 약 1,214★. SQL·mock API 테스트가 있다.

주의: 인덱스·임베딩 없이 쓸 수 있다는 말은 쿼리 비용이 없다는 뜻이 아니다. 기본 20행씩 묶어 API에 보내고 결과를 세션에 캐시한다. 작성자 측정 2,000행 첫 실행 약 3.5초·약 $0.012는 작성자 보고·환경 조건부. 원격 API를 쓰면 행 데이터가 외부로 전달된다. 설치에는 PostgreSQL 14–17의 plpython3u와 superuser 권한이 필요해 일반적인 관리형 DB에서는 안 될 수 있다.

4. 우리 입장: 어디부터 써볼까

첫째, 브라우저 구조와 코드 검색을 작은 실험으로. 브라우저 코드는 ‘동작+대상 동시 선택’과 실행 전 DOM 재확인을 참고할 가치가 있다. 다만 우리 사이트 업무 한두 개에 대해 성공률·총비용·실패 복구를 기존 방식과 같은 조건에서 재야 한다. 코드 검색은 현재의 rg·의미 검색과 동일한 질문 묶음으로 비교하고 Jev 호출 비용까지 합산한다.

둘째, 압축은 복원 가능성을 우선한다. 삭제된 도구 응답을 나중에 다시 읽을 수 있는 작업에만 실험하고, 파일 경로·오류 로그·사용자 제약이 살아남는지 검수한다. 확률 점수 하나로 중요한 대화 맥락을 버리지 않는다. SQL 확장은 외부 전송 가능 데이터와 관리 권한을 먼저 판단한다. 트레이더는 코드 사례로만 읽는다.

이 판단은 Jev의 정확도 한계, 값싼 LLM과의 실제 비용 비교, 고위험 결정 게이팅의 주의점과 일치한다. 빠른 확률 출력은 유용한 구성요소이지, 결과를 독립 검증하지 않아도 되는 면허가 아니다.
