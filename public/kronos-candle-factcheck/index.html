Kronos는 120억 개 이상의 금융 봉 데이터로 사전학습한 공개 시계열 모델이다. 실재하는 연구지만, “100% 무료로 다음 움직임을 정확히 안다”는 거래 시스템의 증거는 아니다.

2026.10.20 확인 · 원문 2026.10.19 UTC · 논문 최초 공개는 2025.08.02

판정: 모델은 진짜. 수익·확신은 미입증.

확인 — 공식 코드·모델이 있고, 논문은 45개 거래소의 120억+ K-line 학습 기록을 보고한다. Kronos-small은 약 24.7M 파라미터, 문맥 512봉이다.

원문 교정 — 기본 예측 API는 여러 샘플을 내부에서 평균낸다. sample_count=100만으로 100개 경로와 위험 구간이 반환되는 것이 아니다.

미검증 — 모든 노트북에서 쾌적한 실행, 다음 움직임의 정확한 예견, 검증된 수익, 보정된 확률·위험, 전체 시스템 무료라는 주장.

검증 범위: 원문, 공식 논문 초록·저장소·구현 코드·Hugging Face 메타데이터, Binance API·TradingView 차트 문서를 읽었다. 모델 다운로드·추론·백테스트·모의/실거래·거래소 계정·봇 연결은 전혀 하지 않았다.

실체와 날짜100개 샘플의 함정입력·노트북·무료연구와 거래 구분출처

01 / 새로 나온 “미래 예측기”는 아니다

@RohOnChain의 원문은 10월 19일 16:27 UTC(한국 10월 20일 01:27)에 게시됐다. Kronos-small을 Mac M5 Pro에서 실행하고, 최근 512봉으로 다음 24봉을 예측한 뒤 Claude로 장세·진입/청산 규칙과 알림을 만든다는 이야기다. 미러의 원 게시물 본문만 확인했으며, 인용된 긴 별도 글을 이 주장에 섞지 않았다.

Kronos 논문이 직접 연결하는 shiyu-coder/Kronos와 공식 README가 연결하는 NeoQuasar/Kronos-small로 실체를 교차 확인했다. 논문 v1은 2025년 8월 2일 13:15 UTC 제출이다. 2026년 10월의 새 게시물이지, 오늘 처음 공개된 모델이 아니다.

“12 BILLION candles”는 논문·공식 모델 카드의 120억+ K-line records, 45개 거래소라는 설명과 일치한다. 이 학습 규모를 우리가 원시 데이터로 다시 집계한 것은 아니다. 모델은 연속 OHLCV 정보를 계층적 이산 토큰으로 바꾸고, 자기회귀 Transformer로 다음 토큰을 생성한다. 여기서 봉은 차트 이미지 한 장이 아니라 시간별 가격·거래 데이터다.

확인한 코드 커밋은 67b630e67f6a(2026-04-13), small 모델 revision은 901c26c13326이다. 코드 LICENSE는 MIT, small과 공식 기본 tokenizer의 모델 카드도 각각 MIT를 표시한다. 각 배포물의 고지와 조건을 따로 확인해야 한다. 별도 GitHub Release는 확인 시 없지만 코드·Hugging Face 배포가 없는 것은 아니다.

02 / 100개를 생성해도, 기본 반환은 평균 한 개다

원문은 sample_count=100으로 “100개의 가능한 미래”를 얻고, 경로 간 퍼짐으로 실제 위험을 알 수 있다고 말한다. 그러나 고정된 공식 구현의 동작은 중요하게 다르다.

입력을 샘플 수만큼 복제 → 경로 생성·복원 → 샘플 축 평균 → 예측값 반환

auto_regressive_inference는 샘플 축으로 배열을 만든 뒤 preds = np.mean(preds, axis=1)을 수행한다. KronosPredictor.predict()는 그 평균 예측을 DataFrame으로 돌려준다. README도 “forecast paths to generate and average”라고 설명한다.

따라서 기본 API에 숫자 100만 넣어서는 100개 경로의 분산·분위수·방향 일치율을 계산할 수 없다. 원 작성자가 별도 경로 보존 코드를 만들었을 수는 있지만 공개된 원문에는 그 구현이 없어 검증되지 않았다.

원시 경로를 보존하면 그 퍼짐은 신뢰구간인가?

자동으로 그렇지 않다. 샘플의 다양성은 모델·온도·top-p 설정 아래에서 생성된 분포다. 실제 미래가 어느 비율로 그 안에 들어오는지 별도 홀드아웃에서 보정·커버리지를 평가해야 확률 구간의 의미를 논할 수 있다. 경로가 모두 같은 방향이어도 데이터 편향·체제 변화·공통 모델 오류로 함께 틀릴 수 있다.

“TRENDING / CHOPPY” 분류도 원 작성자의 후처리 제안이다. 공식 Kronos가 보장하는 검증된 매매 신호나 위험 등급이 아니다.

샘플 100개는 공짜 정확도 버튼도 아니다. 구현은 입력과 타임스탬프를 샘플 수만큼 반복해 배치를 키운다. 메모리와 연산 요구가 증가하지만 병렬 처리와 장치에 따라 달라지므로 실제 시간·메모리가 정확히 100배라고 단정하지 않는다.

03 / 512→24, 노트북, 무료를 나눠 읽기

원문 주장과 공식 자료 대조
주장확인한 사실
최근 512봉 → 다음 24봉small의 최대 문맥 512는 확인. 예측 길이는 설정값이며 24가 보장된 정확도 범위는 아니다.
보통 노트북이면 된다small 약 24.7M. 코드에 CUDA→MPS→CPU 자동 선택이 있다. 모든 기기의 지연시간·메모리·호환성은 미측정.
100% 무료 시스템MIT 코드·모델은 공개. Claude 구독/API, 하드웨어·전력·운영·데이터 조건까지 무조건 무료인 것은 아니다.
TradingView와 같은 Binance 봉심볼·거래소·상품·시간 구간·완성봉 조건을 맞춰야 비교 가능. 모든 차트의 데이터가 자동으로 같아지지 않는다.
미래 움직임을 정확히 안다예측을 만드는 모델이다. 원문의 재현 로그·시간외 평가·비용 차감 수익은 공개 자료로 확인되지 않았다.

공식 모델군은 mini 4.1M/문맥 2048, small 24.7M/512, base 102.3M/512다. large 499.2M은 README상 미공개다. small 가중치 메타데이터의 F32 파라미터 수는 24,741,696개지만 그 용량만으로 런타임 전체 메모리를 계산할 수 없다. tokenizer·중간 활성값·프레임워크·샘플 배치도 필요하다.

입력은 최소 open, high, low, close를 요구하고 volume, amount는 선택이다. 원문처럼 종가를 빼거나 타임스탬프를 잘못 맞추면 같은 입력이 아니다. “24봉”도 1분봉이면 24분, 1시간봉이면 24시간이며 거래 세션·결측 처리에 따라 시간 범위가 달라진다.

Binance 공식 문서의 GET /api/v3/klines는 심볼과 지원 interval을 받으며 기본 시간대는 UTC, 요청당 limit은 최대 1000이다. 봉의 시작 시각으로 구분하고 종가·거래량·quote asset volume 등을 별도로 반환한다. 임의의 코인·임의의 주기가 다 지원된다는 뜻은 아니다.

TradingView에서 다른 거래소·현물/무기한·지수·다른 시간 경계를 보고 있으면 Binance 현물 데이터와 다를 수 있다. 이는 데이터 정의상 비교 조건에 대한 판단이며 실제 두 피드를 계측한 결과가 아니다. Lightweight Charts는 데이터를 setData로 넣어 그리는 라이브러리이지, TradingView의 유료/독점 데이터나 예측 정답을 함께 제공하는 서비스가 아니다. 공식 문서상 TradingView 고지·링크 표시 조건도 있다.

04 / 예측 실험과 매매 시스템 사이에는 검증이 있다

논문은 가격 예측 RankIC, 변동성 MAE, 합성 데이터 fidelity 개선을 보고한다. 순위상관·예측 오차·생성 품질은 수수료 차감 수익률이 아니다. 연구 저자의 벤치마크 성과를 원문의 “다음 움직임을 정확히 아는” 개인 시스템 증거로 바꿀 수 없다.

공식 README도 미세조정·Qlib 백테스트 예제를 단순한 시연이며 production-ready quantitative trading system이 아니라고 명시한다. 시장·스타일 위험 중립화, 포트폴리오 구성, 거래 비용·슬리피지·시장 충격 등을 별도 검토해야 한다고 적혀 있다.

  1. 먼저 시간 분리. 과거 데이터로 규칙과 설정을 고른 기간과 평가 기간을 분리하고, 학습 데이터 중복 가능성·미래 정보·아직 끝나지 않은 봉의 유입을 점검한다.
  2. 단순 기준과 비교. 직전 값 유지나 단순 통계 기준과 같은 입력·같은 시점에서 비교한다. 예쁘게 맞은 구간 하나만 골라 보여 주지 않는다.
  3. 확률을 따로 평가. 여러 샘플을 보존했다면 실제 미래를 포함하는 비율·분위수 보정 등을 홀드아웃에서 확인한다. 모델 내부 일치율을 현실 정답 확률로 부르지 않는다.
  4. 거래 성과는 별도 지표. 거래 규칙의 선택 편향, 수수료·슬리피지·시장 충격·체결 가능성·낙폭을 포함한 시간외 검증 없이는 수익 전략이라고 판정할 수 없다. 과거 결과도 향후 성과의 보장이 아니다.

위 항목은 연구 결과를 해석하는 검증 기준이다. 이 조사에서 진입·청산·손절 가격이나 개인 투자 결정을 제안하지 않았고, 원문이 제안하는 거래·모의거래·알림 봇을 만들지 않았다.

최종 결론: Kronos는 공개 코드·가중치가 있는 금융 시계열 연구 모델이다. 120억+ 학습 규모는 저자 자료와 맞고, small의 512봉 문맥도 확인된다. 하지만 “100개 샘플 = 검증된 위험”, “미래를 정확히 아는 무료 거래 시스템”이라는 확대 해석은 근거가 없다. 가장 먼저 고칠 부분은 기본 API가 경로를 평균낸다는 사실이다.
