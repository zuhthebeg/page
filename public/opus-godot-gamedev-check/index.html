Opus와 Godot로
6주 만에 게임을 만들었다?

@rewind02의 2026-10-24 게시물은 코딩 경험 없는 개발자가 Claude Opus 5.5와 Godot로 6주 만에 게임을 만들었다며 8단계 제작법을 소개했다. 원 개발자의 게시물까지 거슬러 올라가니, 6주차 개발 영상은 진짜지만 첫 외부 플레이테스트도 아직 전이었다.

원출처 추적도구 라이선스우리 적용 판단

6/10판정: 개발 중인 게임과 6주 기록은 확인. 완성·출시와 ‘무경험’은 미검증.
✓ 개발자 본인 5주 제작기·6주차 트레일러△ Tripo·Cascadeur 이용 조건은 플랜별로 다름✗ 플레이 가능한 출시작 확인 못 함✗ 코딩 경험 없음·8단계 전부 사용은 재가공 게시물만으로 입증 안 됨

1. 원출처: 누가 무엇을 만들었나

재가공 글의 ‘dev: afterthewinddev’는 실존하는 @afterthewinddev다. X 프로필 이름은 After The Wind이고, 게임 인스타그램을 연결해 둔다. 개발자 본인의 10월 20일 게시물은 “5주차”라며 아이디어→자료 조사→Claude Code와 Codex로 구현→게임 안에서 판단·반복한다고 설명한다. 10월 23일 6주차 게시물에는 1분 13초 트레일러가 있다. 즉 프로젝트와 개발 영상의 존재는 확인된다.

그러나 개발자는 같은 6주차 글에서 “첫 플레이테스트를 할 수 있기를 기다린다”고 썼다. Steam·itch 등 플레이 가능한 배포 페이지는 이번 조사에서 확인하지 못했다. 따라서 “6주 만에 출시 가능한 완성 게임”이라고 부르면 원 개발자의 표현보다 앞서간다. 작업 시작일·총 작업 시간·코딩 무경험 여부도 독립 자료가 없다. 개발자 자기소개와 재가공 글을 혼동하지 말아야 한다.

2. 주장별 근거 등급

주장확인한 자료판정
After The Wind 프로젝트와 6주차 영상개발자 본인 게시물·영상확인: 공개 개발 기록 존재
Claude Code + Codex로 기능별 개발·게임 내 반복5주차 본인 설명자기 보고: 사용 과정, 독립 재현 아님
6주 만에 ‘게임 완성’본인은 첫 플레이테스트 예정이라고 표현완성·출시 미검증
코딩 경험 없음재가공 게시물의 주장독립 검증 불가
JSON 프롬프트·Tripo P2·Blender·Cascadeur·Obsidian 전부 실제 사용재가공 글의 8단계; 개발자 본인 확인은 Claude Code·Codex 및 반복 루프까지나머지 개인 워크플로는 미검증

여기서 ‘확인’은 게시물과 영상의 존재, ‘자기 보고’는 개발자의 사용 설명, ‘미검증’은 별도 근거가 부족하다는 뜻이다. 영상만으로 소스 코드·에셋 출처·완성도를 보증할 수 없다.

3. 제작 도구: 돈과 라이선스까지 보면

Tripo Smart Mesh P2.0공식 가격표에 P2.0 크레딧 항목 존재. Free $0·월 200크레딧, 공개 모델·비상업. Pro 연간 결제 기준 월 $20($240/년)·월 3,000크레딧, 비공개 모델·상업 이용. P2.0 생성은 일반 모델보다 추가 크레딧이 들 수 있어 ‘월 200개’ 표기를 P2 산출량으로 읽으면 안 됨.유료 실험 전 플랜·크레딧 소모 확인

‘Codex/Astra’개발자 본인은 Claude Code·Codex를 언급한다. 재가공 글의 ‘Astra’는 제품·모델·이미지 생성 서비스 중 무엇인지 특정할 링크가 없다. Codex가 직접 이미지 생성했다고 단정할 근거도 없다.도구 정체와 가격·이미지 이용 조건 미검증

가격은 공식 공개 페이지의 조사 시점 USD 표기이며 세금·결제 방식·변경에 따라 달라진다. Tripo 약관은 유료 권리를 설명하지만, 그 자체가 타인의 이미지를 참고해 만든 결과물의 권리 안전성을 보장하지는 않는다.

4. 우리도 쓸 수 있나

쓸 수 있다. 다만 Godot로 갈아탈 이유는 아직 없다. 우리는 이미 Claude Code(Opus) 중심으로 웹 게임을 운영한다. ARPG 언타이틀은 Godot가 아닌 PixiJS 웹 게임이다. 웹에서 바로 플레이하고 광고 수익을 내는 구조를 위해 현재 웹 스택을 유지하는 편이 낫다는 것이 우리의 평가다. Godot의 웹 배포가 불가능하다는 뜻은 아니다.

즉시 도입: 잘 된 이미지 프롬프트를 JSON 레지스트리로 남긴다. 기존 로컬 FLUX.1-dev GGUF/SDXL 생성, LoRA·img2img 캐릭터 일관성 작업에 프롬프트·모델·시드·레퍼런스·승인 결과를 함께 기록한다. 재가공 글의 방법 자체를 우리 자산으로 만드는 비용은 거의 없고, 스타일 변경 원인을 추적하기 쉽다. 스타일 드리프트가 자동으로 사라진다는 보장은 아니다.

계속할 것: 기능 하나씩 구현→플레이테스트→수정하는 루프는 이미 하고 있다. 3D 에셋은 현재 KayKit·Poly Pizza의 CC0 모델을 몬스터 8방향 스프라이트 아틀라스로 베이크한다. Blender 5.2 MCP를 통한 GLB→Three.js 연결도 완료했다. 이 기반에서 Tripo는 CC0 모델이 없는 커스텀 몬스터·보스가 필요할 때만 유료 생성→기존 베이크 파이프라인 투입을 시험할 수 있다. 아직 실제 게임에 Tripo 생성물을 도입했다는 뜻이 아니다.

우선순위 낮음: Cascadeur 새 리깅·애니메이션 작업보다 이미 사용 가능한 리깅된 CC0 모델 애니메이션 재사용이 스프라이트 베이크 구조에선 저렴하다. VFX·셰이더를 문서화하는 습관은 유용하지만 Obsidian 자체로 옮길 필연성은 없다. JSON의 핵심은 특정 앱이 아니라 스타일 결정을 재사용 가능하게 남기는 것이다.

5. 결론

AI로 6주 동안 눈에 보이는 게임 프로토타입을 만든 사례로 볼 근거는 있다. 6주 완성작, 무경험 개발자의 모든 도구 사용법을 검증한 성공 공식으로 읽을 근거는 부족하다. 우리에게 이식할 것은 엔진·유료 툴 목록보다 좋은 레퍼런스와 프롬프트를 남기고, 작은 단위로 게임 안에서 판단하는 운영 방식이다. Tripo는 필요한 커스텀 에셋이 생겼을 때 유료 조건을 확인해 좁게 시험한다.
