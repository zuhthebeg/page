Model check · Follow-up to laya-check

laya-mlx,
Jev보다 정말 50배 빠른가?

atomic.chat(@atomic_chat_hq)이 "맥북에어에서 로컬로 돌린 laya가 클라우드 Jev를 11배 빠른 판단으로 테트리스에서 이겼다"는 영상을 올렸다. 인용한 원 트윗(@mizorewww)은 "Jev보다 50배 빠른 버전"이라고 laya-mlx를 소개한다. 둘 다 확인했다 — laya 자체는 이미 별도로 검증했으니, 여기서는 이번에 나온 MLX 포팅과 두 속도 주장만 본다.

7/10판정: MLX 포팅은 진짜고 빠르다, 그런데 "50배"는 저장소 문서에도 없는 숫자다

2. "Jev보다 50배 빠르다" — 어디서 나온 숫자인가

인용 트윗(@mizorewww, laya-mlx 제작자 본인)은 "Jev보다 50배 빠른 버전"이라고 못박는다. 그런데 저장소의 README와 BENCHMARKS.md를 전체 검색해도 "Jev"라는 단어도, "50"이라는 배수도 나오지 않는다. 저장소는 자기 모델의 절대 지연시간만 보고한다:

영어 체크포인트M3 Max에서 P50 13.42ms / P95 13.92ms
다국어 체크포인트M3 Max에서 P50 7.39ms / P95 7.79ms

Jev 쪽 숫자는 이전 검증과 Jev 게이트웨이 리뷰에서 쓴 것과 같은 제3자 측정치를 그대로 쓴다 — TypeSafe API 접근 없는 독립 벤치마크 2곳이 측정한 P50 236~296ms(과업별로 다름, 클라우드 호출 기준). 이 둘을 직접 나누면:

비교배수
영어 체크포인트 (13.42ms) 기준17.6~22.1배
다국어 체크포인트 (7.39ms) 기준31.9~40.1배

가장 유리하게 계산해도(다국어 체크포인트 vs Jev 최악 케이스) 40배 근처가 최댓값이고, 대표값으로 보면 20~30배대다. "50배"에 닿으려면 Jev를 실제보다 더 느린 조건으로 잡거나, laya-mlx 쪽에서 문서화되지 않은 더 빠른 설정(컴파일·prefix-reuse 등)을 썼을 가능성이 있는데, 어느 쪽이든 트윗에 근거가 안 달려 있다. 기술은 진짜 빠르다. "50배"라는 숫자만 부풀려졌다.

3. 테트리스에서 "11배 빠르다"는 영상은 얼마나 믿을 만한가

atomic.chat 본문 트윗의 핵심 주장은 다르다 — 실제 게임(Grok 4.7로 만든 테트리스)에서 laya가 Jev보다 11배 빠른 판단으로 이겼다는 것. 이건 위의 원-질문 API 벤치마크와 별개로, 게임 루프 안에서 실측한 수치라는 뜻이다.

흥미로운 지점: 11배는 방금 계산한 20~40배대보다 오히려 낮다. 이건 오히려 자연스럽다 — 실제 게임에서는 Jev가 클라우드 호출이라 네트워크 왕복 시간이 더해지는데, 그럼에도 11배면 라야 쪽이 유리한 조건을 다 반영해도 보수적인 숫자로 보인다는 뜻이다. 즉 수치 자체의 방향은 그럴듯하다.

다만 검증 가능성은 다른 문제다. laya-mlx 저장소가 공개한 건 스네이크 데모(코드·측정 방법론·GIF·MP4 전부 저장소에 있음)이고, 테트리스는 저장소 어디에도 없다 — atomic.chat이 별도로 만든 데모다. 재현 가능한 벤치마크 코드나 방법론 문서가 공개되지 않았으므로, 이건 회사가 만든 프로모션 영상이지 검증 가능한 벤치마크가 아니다. 숫자의 방향은 믿을 만해 보이지만, "11배"라는 정확한 값 자체를 제3자가 재현할 방법은 없다.

4. 실제로 뭐가 좋은가

과장을 걷어내도 남는 게 있다. laya-mlx는 애플 실리콘에서 진짜로 빠르고 가벼운 판단 엔진을 로컬에 놓는 방법을 제공한다. 특히:

  • 13ms 이하 P50은 실시간 루프(게임 AI, 에이전트 내부 판단)에 충분히 쓸 만한 지연시간이다
  • 1GB 이하 메모리는 맥북 에어급 기기에서도 상주시켜 둘 수 있는 수준
  • 378/378 정합성 검증은 포팅 과정에서 원본 모델의 판단이 바뀌지 않았다는 근거로 이례적으로 꼼꼼하다

단, 이전 laya 검증에서 확인한 한계는 MLX 포팅으로도 사라지지 않는다 — laya 계열 모델은 confidence가 미보정 상태로 나올 수 있다(비라틴 문자권에서 정확도 0%인데 confidence 95%였던 사례). laya-mlx는 원본 가중치·보정값을 그대로 쓰므로, 속도가 빨라졌다고 판단 품질이 좋아진 건 아니다. 빠른 오답도 여전히 오답이다.

결론

laya-mlx는 실재하고, 성실하게 문서화됐고, 빠르다는 것도 사실이다. atomic.chat의 "11배" 영상은 숫자 방향이 그럴듯하지만 재현 불가능한 데모다. 문제는 "50배"라는 가장 화제성 있는 숫자가 정작 laya-mlx 제작자 본인의 벤치마크 문서에는 없다는 것 — 실제로 계산하면 20~40배대다. 이미 충분히 인상적인 결과에 굳이 더 큰 숫자를 얹은 셈이라, 이 부분만 걸러서 보면 된다.
