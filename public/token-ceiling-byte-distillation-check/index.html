RESEARCH NOTE · CLAIM CHECK

토크나이저 없는 1B가
LLM 시대를 끝낸다?

핵심은 ‘256바이트가 모든 모델을 이겼다’가 아니다. 큰 토큰 모델의 지식을 작은 바이트 모델로 옮겼을 때, 학습량에 따른 성능 곡선이 어떻게 달라지는지를 조사한 연구다.

작성·확인: 2026-11-15 · 원 게시물: 2026-11-14 · 논문 v1: 2026-09-11 · 문헌 검토 / 추론 재현 없음

판정: 실재하는 유망한 연구. ‘LLM 종말·전면 SOTA’로 읽으면 과장이다.

바이트 증류 방법과 스케일링 실험은 확인된다. 그러나 1/6 데이터와 Llama·Gemma 우위의 핵심 숫자는 곡선을 연장한 예측이고, 80% 절감은 교사 로짓 저장량이다. 가중치·VRAM·서비스 비용이 80% 줄었다는 뜻이 아니다. EOT는 학습에서 교사의 BPE 토큰 경계를 이용하며, 논문은 추론 비용이 여전히 크다고 명시한다.

1. BLT가 아니라, ‘Breaking the Token Ceiling’

@CrazyShyyt의 게시물은 “End-Of-Token”, “1/6”, “저장 비용 80%”를 함께 언급한다. 이 조합은 Breaking the Token Ceiling: Distilling Smaller, Stronger Byte Models(arXiv:2609.12303)과 일치한다. 이름이 비슷한 다른 바이트 연구인 Byte Latent Transformer로 바꿔 읽으면 안 된다.

  • 저자: Kalyani Marathe, Artidoro Pagnoni, Tomasz Limisiewicz, Margaret Li, Mike Lewis, Luke Zettlemoyer, Srinivasan Iyer. 워싱턴대학교 시애틀·Meta FAIR 공동 연구다. PDF 첫 페이지는 두 소속을 명시하고, Marathe의 연구가 Meta FAIR에서 수행됐다는 주석을 단다. HTML 변환에는 소속 표기가 일부 누락돼 PDF를 우선했다.
  • 날짜: arXiv 제출 이력은 2026-09-11 00:17:22 UTC의 v1. 11월 게시물보다 약 두 달 앞선 논문이다. 게시물은 “published a paper”라고 했으며, ‘방금 공개’라는 표현까지 원문에 덧붙여 반박하지 않는다.
  • 공개와 권리: 논문은 arXiv에서 읽을 수 있고 CC BY 4.0 표기가 있다. 이는 논문의 이용 조건이지 학생 모델 가중치의 상업 이용 허가가 아니다.
  • 코드·가중치: 확인한 arXiv 초록·HTML 본문에서 저자 공식 코드/가중치 링크를 식별하지 못했다. 제목 기반 GitHub 저장소 검색과 HF의 ‘End-Of-Token’ 모델 검색도 공식 배포 확인으로 이어지지 않았다. 검색 범위가 제한돼 있으므로 ‘공개물이 절대 없다’고 단정하지 않는다.

검색에 나오는 ananymishra/token-to-byte-distillation은 ‘adapted from’이라고 밝힌 제3자 소규모 구현이다. GPT-2 교사와 가벼운 학생 모델을 쓰며, 확인한 README에서 대규모 학습·저장 압축 평가 단계는 미완료다. MIT 표기는 이 저장소의 조건일 뿐 Meta 실험 모델의 배포·재현 증거가 아니다.

2. 게시물의 주장을 나눠 보면

게시물 주장확인한 내용 / 판정
256개 원시 바이트를 읽는 약 1B 모델대체로 맞음. 256 UTF-8 바이트에 특수 기호가 추가된다. Bytes-1B 어휘는 260, EOT는 261. 실제 총 파라미터는 약 1.286B다. [§3, 표1·9]
토크나이저가 필요 없다범위 제한. 큰 BPE 어휘를 학생 출력층에서 없애는 것과 학습 파이프라인 전체에서 토큰 의존성을 없애는 것은 다르다. EOT 학습은 각 BPE 토큰 뒤에 경계 기호를 붙인다. [§2.2]
토큰 모델은 더는 똑똑해지지 않는다일반화 과장. 고정 크기·데이터 구성의 실험에서 포화 경향을 보고했다. 생성 과제의 포화는 덜 뚜렷하다고도 쓴다. 모든 토큰 LLM의 보편적 한계라는 증명이 아니다. [§5.1–5.2]
같은 성능을 데이터 1/6로 달성조건부 예측. 적합한 스케일링 법칙으로 토큰 증류 모델의 점근 성능에 도달할 지점을 계산한 결과다. 교사 사전학습까지 포함한 총 데이터·비용 1/6이 아니다. [§7, 표6·7]
저장 비용 80% 감소대상이 생략됨. 교사 확률분포를 저장하는 오프라인 증류용 로짓 저장량이 약 1/5이라는 계산. 모델 파일이나 VRAM 80% 절감은 아니다. [§7.3, 부록 A.6]
Llama 3.2·Gemma 2B를 모든 면에서 이김근거 범위 초과. 6개 과제 평균의 점근 예측과 기존 모델의 평가 점수를 비교했다. 실제 최대 학습 체크포인트의 평균은 Llama 3.2-1B·Gemma 2B보다 낮다. [표8·18]
토크나이저 없이 SOTA 학습 / LLM 시대 종말이 논문으로 입증되지 않음. 제한된 크기의 dense Transformer 연구다. 전 분야 SOTA나 LLM을 대체하는 새 패러다임의 완성을 검증한 논문이 아니다.

3. 1/6와 80%: 무엇을 얼마나 줄였나

교사는 여전히 Llama 3-8B다

큰 교사의 토큰별 확률분포를 바이트별 분포로 변환하고, 학생이 이를 배우는 지식 증류다. Marginalize-It은 근사 변환, End-Of-Token은 종료 기호를 추가해 확률 질량을 보존하는 변환이다. ‘exact’는 이 변환의 확률 보존을 뜻하며 ‘완벽한 추론’이라는 뜻이 아니다. 변환에 교사 추가 추론을 요구하지 않는다는 설명도 교사 추론 자체가 공짜라는 뜻은 아니다. [§1.1, §2, 부록 A.1]

EOT는 교사 토큰 경계를 사용한다. 따라서 ‘인간식 단어 조각을 전혀 거치지 않고 처음부터 독립적으로 더 똑똑해졌다’는 설명은 이 실험을 제대로 요약하지 못한다.

같은 토큰 수, 같은 바이트 수, 같은 FLOPs는 다르다

층 파라미터 1.28B는 맞췄지만, 큰 입출력 어휘 때문에 Token-1B의 총 크기는 1.81B다. 문맥 길이도 토큰 2,048 / 바이트 9,216 / EOT 바이트 11,264로 다르다. 이 연구를 ‘총 파라미터와 입력 길이까지 모두 같은 대결’로 소개하면 틀린다. [표9]

논문은 토큰 하나를 평균 4.5바이트로 환산한다. EOT에는 그마다 경계 하나가 추가돼 약 5.5 단위가 된다. 단위당 학생 학습 FLOPs는 각각 약 8.18·8.81·9.44×10⁹. 바이트가 더 잘게 나뉘므로 같은 텍스트에는 더 많은 위치 계산이 든다. EOT는 Marginalize-It 대비 동일 텍스트당 약 30.94% 추가 연산도 사용한다. 적은 데이터는 곧 적은 연산·짧은 시간이라는 등식이 아니다. [§2.2, 표9]

표9의 식은 학생 아키텍처의 학습 연산을 계산한다. 교사 사전학습·교사 로짓 생성·변환·입출력까지 합친 전체 프로젝트 비용을 절감했다는 감사 결과가 아니다. 논문은 iso-FLOP 비교도 제시하지만 실제 서비스의 동일 지연시간 비교와는 다르다. [§7.1, 부록 A.1]

1/6는 관측 범위를 넘어선 도달점 계산

표6·7은 토큰 증류 모델의 점근 평균 정확도 48.4%에 EOT가 언제 도달할지 역산한다. EOT에 필요한 것으로 계산한 학생 연산은 6.33×10²² FLOPs, 약 6.70조 바이트 단위. EOT 기호를 빼면 실제 텍스트 약 5.48조 UTF-8 바이트다. 같은 계산 예산의 토큰 방식은 약 34.8조 바이트로 환산돼 6.35배 데이터 절감이 나온다. 이것이 ‘약 1/6’의 맥락이다. [§7.2, 표7]

이는 초록의 ‘최대 1조 바이트 규모’ 실험 범위를 넘어선 외삽이다. 논문은 일부 큰 학습이 데이터를 재사용(epoch)한다고도 밝힌다. 학습 단위 수를 모두 서로 다른 새 원문 데이터로 읽어서는 안 된다. [§10.1]

약 80%는 로짓 덤프 저장량

오프라인 증류는 교사가 낸 분포를 디스크에 저장한다. 비교 실험에서 토큰 방식은 어휘 128,256개 중 상위 600개 로짓과 인덱스, 바이트 방식은 약 260개 전체 분포를 저장한다. 부록 A.6은 동일 텍스트의 저장 비용을 맞춰 top-k≈600을 정한 과정을 공개한다.

표7의 도달점 계산에 데이터 효율과 경계 기호 오버헤드를 반영하면 EOT의 Storage Savings=5.19×, 즉 약 1/5 수준(약 81% 감소)이 된다. 같은 양의 원문을 무조건 80% 작게 저장하거나, 가중치를 80% 압축했다는 실측이 아니다. 비교 토큰 분포는 top-k로 잘리고 EOT는 전체 분포를 보존하므로 이 차이 역시 결과의 조건이다.

4. 실제 점수와 예측 점수를 분리하자

전체 평가는 ARC-Easy·ARC-Challenge·HellaSwag·PIQA, MBPP·Natural Questions, FLORES 영→독·독→영의 8개 평가로 이뤄졌다. 그런데 바이럴 글에 인용된 점근 평균은 번역을 뺀 6개 과제 평균이다. 번역은 BLEU, 다른 표는 정확도를 쓰므로 한데 섞을 수 없다. [§3.3, 그림1, 표18]

표8의 52.4%에서 기준 모델 45.9·44.3·50.3%를 빼면 6.5·8.1·2.1퍼센트포인트다. 이 수치는 ‘이미 나온 1B가 모든 과제에서 앞섰다’가 아니다. 표18의 실제 EOT는 PIQA 71.7로 Llama 75.3보다 낮고, MBPP 11.2로 Llama 27.0보다 낮다. 반대로 ARC-Easy 68.3과 NQ 12.7에서는 Llama의 66.1·5.7보다 높다. 장단점이 갈린다.

읽는 법: ‘실제 EOT 평균 44.6이 Gemma-3-1B-pt 44.3보다 높다’는 해당 표의 관측 사실. ‘충분히 학습하면 52.4에 접근한다’는 저자들의 스케일링 예측. ‘앞으로 반드시 모든 LLM보다 좋아진다’는 이 자료가 뒷받침하지 않는 주장이다. 관측 표도 같은 총 학습 예산으로 맞춘 상용 모델 대결은 아니다.

외삽은 무의미한 숫자가 아니라 검증할 가치가 있는 연구 가설이다. 다만 저자들이 민감도 분석을 실었다고 해서 예측값이 실측으로 바뀌지는 않는다. 또한 고정 크기 토큰 학생의 포화가 토큰 기반 모델 전체의 개선 중단을 증명하지도 않는다. [§10, 부록 D]

5. 지금 어디에 쓸 만한가

연구 관점: 작은 모델의 오프라인 증류에서 큰 어휘의 확률 정보를 어떻게 보존할지, 로짓 저장과 학생 학습 데이터 효율을 어떻게 비교할지 살펴볼 자료다. 토크나이저 선택이 단순 전처리가 아니라 학습·연산 예산의 설계 변수라는 점이 유용하다. 이 문단은 문헌 기반 평가다.

바로 쓸 로컬 챗봇 관점: 현재 확인 범위로는 추천할 단계가 아니다. 공식 학생 체크포인트·모델 카드·모델 라이선스와 특정 런타임 로더를 확보하지 못했으므로 다운로드 크기, VRAM, 초당 생성량, API/브라우저 지원을 단정할 수 없다. 제3자 PyTorch 데모의 존재가 공식 1.286B 체크포인트의 llama.cpp·Ollama·WebGPU 호환성을 증명하지 않는다.

“End-Of-Token-1B models remain significantly expensive at inference time.” — §10, Inference Costs

저자들은 같은 추론 비용으로 맞춘 토큰 모델과의 비교가 연구 범위 밖이라고 명시한다. 부록 A.4의 학습은 실행당 64 H200을 사용했다. ‘1B니까 소비자 GPU로 싸고 빠르게 재현’이라는 결론을 붙일 근거가 없다. 이 페이지에서는 설치·모델 다운로드·추론을 하지 않았고 GPU 성능을 측정하지 않았다.

한국어 업무·도구 호출·안전한 JSON·긴 문맥 품질은 이 표로 확인되지 않는다. 후속 공개물이 나오면 가중치/권리 → 런타임 지원 → 고정 한국어·JSON 과제 → 지연시간·메모리 순서로 확인하는 게 맞다. 이 수용 시험은 제안이며 실행 결과가 아니다.

결론

배울 것은 ‘토큰을 버리면 마법처럼 더 똑똑해진다’가 아니다. 작은 바이트 학생의 증류는 데이터·확률 보존·연산량 사이에서 다른 스케일링 경로를 보인다는 것이다. 토큰 교사 의존성, 외삽, 로짓 저장이라는 분모를 지우면 연구 소개가 과장으로 바뀐다. ‘LLM 종말’ 대신, 추가 학습과 공개 재현으로 확인할 만한 작은 모델 연구로 읽자.
