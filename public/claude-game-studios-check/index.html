AI 게임 회사 차리기?

@dopamine_crypto 게시물은 Claude Code를 "AI 직원 49명, 스킬 74개, 문서 템플릿 62개"짜리 게임 회사로 바꿔주는 저장소 Claude-Code-Game-Studios(★2.7만)를 소개한다. 저장소를 받아 직접 세어 봤다. 숫자는 다 맞다. 그런데 가장 중요한 숫자는 게시물에 없고 README에 있다.

1. 실제로 들어 있는 것

코드가 아니라 Claude Code 설정 묶음이다. 새 게임 프로젝트를 이 템플릿으로 시작하면 .claude/ 폴더에 아래가 깔린다.

  • 에이전트 49개: 디렉터(비전 관리) → 리드(기획·프로그래밍·아트·사운드 등) → 실무자 3단 구조. Godot·Unity·Unreal 전용 전문가 세트 포함.
  • 스킬 74개: /start, /design-system, /create-epics, /create-stories, /dev-story, /story-done 같은 단계별 명령.
  • 훅 15개: 커밋·푸시·파일 쓰기·에셋 변경 때 자동 검사. 외부로 나가는 건 GitHub에 새 릴리스가 있는지 확인하는 업데이트 체크 하나뿐이다(api.github.com).
  • 규칙 14개: 게임플레이·엔진·UI·네트워크·셰이더 코드 등 경로별 코딩 규칙.
  • 문서 템플릿 71개: 게임 기획서, UX, 스프린트, HUD, 접근성 등.

2. 게시물이 빠뜨린 가장 중요한 대목

README에 "이게 게임을 만드나, 문서를 만드나?"라는 절이 있다. 제작자가 같은 기획 한 장으로 게임 4개를 만들어 비교했다.

엄격도(modes.rigor)코드 전 작성 문서문서에 쓴 시간
minimal1개 (기획 한 장)0분
standard30개58분

전부 실행되고 테스트도 통과했다. 그런데 블라인드 리뷰어 2명과 사람 플레이테스트에서 문서 30개짜리 standard 버전이 꼴찌였다. 제작자의 결론: "추가 문서 29개는 추적성을 산 것이지, 더 좋은 게임을 산 게 아니다."

즉 이 템플릿의 진짜 가치는 "49명 회사"가 아니다. 제작자도 문서 엄격도를 최소로 낮추는 걸 기본 선택지로 둔다. 엄격도와 상관없이 지키는 규칙은 하나다. 화면에 보이는 걸 바꾼 작업은 게임을 실제로 실행해서 보고, 스크린샷을 남겨야 완료 처리된다. "테스트 통과"만으로는 메뉴가 화면 밖에 그려진 걸 못 잡기 때문이다.

4. 쓸 때 조심할 것

  • 토큰 비용: 에이전트 49개가 위아래로 검토를 주고받는 구조라, standard 엄격도는 한 기능에도 호출이 많다. 제작자 측정으로 코드 전 문서 작업만 58분이다.
  • 엔진 전제: 전문가 세트가 Godot·Unity·Unreal 기준이다. 웹(PixiJS·캔버스) 게임용 전문가는 없다.
  • Claude Code 전용: 훅·스킬 구조가 Claude Code 설정 형식이다. 다른 에이전트에는 그대로 안 붙는다.

5. cocy 판단 — 우리 게임 개발에는?

통째로 도입은 안 한다. 부품 세 개만 가져온다. 우리 게임은 웹 기반이고, 이미 설계는 Opus·반복 구현은 위임하는 분업이 돌고 있어서 49명 조직도는 과하다. 가져올 것은 ① "화면 바뀐 작업은 실행해서 보고 스크린샷 남겨야 완료" 게이트(우리가 워커의 PASS 보고를 믿었다가 빈 결과물을 받은 사고와 정확히 같은 문제를 막는다), ② 경로별 코딩 규칙(게임플레이·네트워크·UI 파일마다 다른 규칙 자동 적용), ③ 엄격도 스위치(프로토타입은 minimal, 출시 직전만 standard). 무엇보다 이 저장소에서 제일 값진 건 제작자가 자기 도구의 한계를 직접 재서 공개했다는 점이다.
