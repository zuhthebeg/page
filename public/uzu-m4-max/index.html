M4 Max로 어디까지?
92.1 tok/s보다
먼저 볼 조건.

9B는 현실적이다. 27–32B는 RAM과 컨텍스트를 골라야 한다. 70B는 64GB부터 조건부 후보. 하지만 M5에서의 uzu 가속을 M4 Max의 약속으로 옮길 수는 없다.

2026.10.28 출처 확인 · M4 Max 실측 없음

판정: M4 Max는 유력한 로컬 머신. uzu의 4배 가속은 별개다.

핵심 발견: 현행 Qwen3.5-9B-M의 speculation 장치 설정에는 M4가 없다. 로더는 장치명과 default 설정이 모두 없으면 speculator를 로드하지 않는다.

M4 Max에서는 우선 일반 생성 성능으로 계획하고, uzu·MLX·llama.cpp의 실제 지원 모델과 메모리로 엔진을 고른다. M5 수치 × 대역폭 비율로 구매나 상시 운영을 결정하지 않는다.

검증 범위: 문서·코드·모델 카드와 파일 메타데이터를 조사했다. 실제 M4 Max의 RAM·GPU 구성을 확인하거나 추론을 실행하지 않았다. 실용 속도 범위는 추정이며 22.0·25.1·92.1은 게시자의 자기보고다. 설치·모델 가중치 다운로드·유료 API 호출·SNS 홍보는 하지 않았다.

01 / 4배라는 숫자의 정체

Avi Chawla의 2026년 10월 27일 게시물은 기본 M5 MacBook Pro의 Qwen3.5 9B를 llama.cpp 22.0, MLX 25.1, uzu 92.1 tok/s로 실행했다고 말한다. 약 4.19배는 그 실행의 비교이지 모든 모델·언어·기기의 가속률이 아니다. 게시자는 공동창업자의 해설도 안내한다. 독립 표준 벤치마크로 취급하지 않는다. [1]

M5, M4 실측 아님

원문 텍스트만으로는 엔진 commit, 세 엔진의 정확한 양자화 파일·품질 등가성, 입력·출력 토큰 수, 컨텍스트 길이, 과제·샘플링·cold/warm 조건을 재현할 수 없다. 나란한 영상은 유용하지만 완전한 평가 설정은 아니다. decode 속도 ≠ 첫 토큰 시간(TTFT) ≠ 전체 지연이다.

현행 공식 9B 카드에는 별도로 M5 Max 128GB / 273 tok/s가 있다. 2026-10-20의 uzu 0.6.9 등으로 측정한 Mirai 자체 데이터 혼합 평균이다. STEM·산문·기타의 21개 데이터셋을 각각 같은 가중치로 평균하고 기본 sampling을 쓴다. 기본 M5의 92.1과 같은 실험이 아니다. 9월 기술 블로그의 MT-Bench 80 / MATH-500 128 / HumanEval 128 표본, 일반 생성용 1,355-token 고정 입력 설명과도 버전이 다르다. 현행 평가도 모든 prompt/output 길이와 비교 설정을 이 글에서 완전 재현한 것은 아니다. [2][3]

02 / 한 번 읽어서 여러 토큰을 얻는다

153 GB/s ÷ 5.2 GB ≈ 29 tok/s는 원문이 쓴 batch-1 일반 생성의 가중치 읽기 근사다. 캐시·KV·활성값·실효 대역폭·커널 비용을 무시한 장난감 모델이지 절대적인 하드웨어 법칙은 아니다. speculative decoding은 토큰마다 본 모델을 따로 실행한다는 전제를 바꾼다.

DFlash 병렬 초안 → Weaver 후보 트리 → 본 모델의 묶음 검증 → 수락 경로 출력

현행 9B speculator config에서 block_size=16, 6개 초안 transformer layer, target layer 8곳의 특징 사용을 확인했다. Weaver는 model_dim 2048의 1-layer autoregressive 구성이다. 공식 기술 블로그도 DFlash의 위치별 top-k 후보를 Weaver가 일관된 경로로 연결하고, 본 모델의 Gated DeltaNet 트리 검증을 수행한다고 설명한다. [3][4]

Weaver 56.7M 파라미터와 평균 7.5 tokens/pass는 게시물 수치다. 구조는 확인했지만 정확한 텐서 합계나 그 실행의 원시 로그는 독립 검증하지 않았다. 작은 Weaver만 추가되는 것도 아니다. 9B 본체 safetensors는 5,189,121,136 bytes, speculator 파일은 755,228,072 bytes. 합계 약 5.94 GB이며 카탈로그는 6.0 GB다. 본체 5.2GB만 RAM 예산으로 잡으면 초안과 런타임을 빠뜨린다. 모델 파일은 받지 않고 HF 메타데이터를 읽었다. [4]

“lossless”의 조건

정확한 speculative sampling은 동일한 대상 모델·동일한 sampling 규칙에 대해 올바른 검증/보정이 구현된 경우 대상 분포를 보존하는 개념이다. greedy 일치와 확률분포 일치는 다르며, 커널·부동소수점 차이까지 항상 토큰 동일이라는 보증은 아니다. Mirai는 Gumbel coupling 검증을 설명한다. 이 글은 해당 구현을 수학적으로 감사하거나 출력 동등성을 실험하지 않았다.

Mirai-M은 4-bit 비대칭 가중치, 4-bit zero point, BF16 scale, group size 32이며 PTQ 뒤 quantization-aware distillation을 거친다. M5의 동적 int8 활성값과 Hadamard 변환을 블로그가 “virtually lossless”라 부르는 것은 근사 품질 설명이다. 원본 BF16과 무손실 동일, 한국어 정확도 보장, 환각 제거라는 뜻은 아니다. [3][5]

03 / M4 지원과 M5 최적화는 다르다

공식 문서는 Apple Silicon macOS/iOS를 지원한다. M4 Max도 그 플랫폼에 속하지만 모든 모델·기능을 기기별 인증한 표는 아니다. M5 GPU Neural Accelerator의 int8 matrix/GEMM 경로는 M5에 맞춘 최적화다. M4에서 같은 하드웨어 경로를 이용한다고 읽으면 안 된다. [3][6]

현재 출고 구성에서 확인한 제약

9B speculator/shapes.json에는 M5·M5 Pro·M5 Max 등의 설정이 있지만 M4 Max나 default는 없다. DFlashTfmSpeculator::load는 둘 다 없으면 Ok(None)을 반환한다. benchmark README도 DFlash를 M5·M5 Pro·M5 Max에서만 켠다고 적었다. 즉 현행 9B 구성으로 M4 Max에서 “평균 7.5개 수락·4배 가속”을 기대할 근거가 없다. 미래 지원이 불가능하다는 뜻은 아니다. [4][7]

2026-10-28 공식 카탈로그에는 Qwen3.5 0.8/2/4/9B, Qwen3.6·3.8 27B, Muse Glimmer 30B, LFM2.5 계열의 Mirai-M/L 등이 있다. Qwen3-32B와 Llama-3.3-70B 지원은 이 목록에서 확인하지 못했다. 아래 32B·70B는 일반 MLX/llama.cpp 계열의 별도 모델 검토이지 uzu 실행 약속이 아니다. 9월의 “일부 27B 곧 지원”보다 현행 목록을 우선했다. [8]

엔진과 모델의 라이선스도 분리한다

uzu 엔진은 MIT. Qwen3.5-9B-M 카드는 Apache-2.0과 원본 Qwen LICENSE를 안내한다. 엔진 MIT가 임의의 가중치까지 허용하지 않는다. 아래 Llama 70B는 Llama 3.3 별도 라이선스다. 제품화·재배포 때는 모델 및 초안 산출물의 실제 고지를 확인해야 한다. [5][9][12]

04 / RAM별로 달라지는 현실적인 상한

Apple 공식 사양은 14-core CPU / 32-core GPU = 410 GB/s, 16-core CPU / 40-core GPU = 546 GB/s다. 흔히 말하는 “400”이 아니라 정확히 410이다. 36GB는 14-core M4 Max, 48·64·128GB는 16-core M4 Max 구성이다. 사용자의 정확한 구성을 확인하지 않았다. [10]

메모리 중심 조건부 추천 · 실측 아님
통합 RAM / GB/s9B · 약 6GB27–32B · 15.6–18.4GB70B · 39.7GB
36GB / 410우선 추천짧은 컨텍스트부터, 앱·KV 점검비추천. 가중치부터 초과
48GB / 546여유 있음유력한 실용 구간비추천. OS·KV 여유 부족
64GB / 546여유 있음컨텍스트 확대 후보짧은 컨텍스트·1인용 조건부
128GB / 546용량보다 속도 선택긴 컨텍스트·병행 앱 여지용량상 유력. 속도 별도 검증

27B는 공식 Qwen3.8-27B-M 카탈로그 15.6GB. 32B는 mlx-community/Qwen3-32B-4bit safetensors 합계 18.43GB, 70B는 mlx-community/Llama-3.3-70B-Instruct-4bit 39.69GB. 양자화·초안 포함 범위가 다르므로 “파라미터 × 0.5 byte”로 대체하지 않았다. 디스크 파일 크기와 실제 peak RAM은 다르다. 두 MLX 예시는 uzu 지원과 분리한다. [11][12]

OS·KV·임시 버퍼가 남아야 진짜로 들어간다

계획용 여유 예산으로 OS·브라우저·앱 8–12GB, 런타임·임시 버퍼 2–4GB 이상을 먼저 남기는 보수적 접근을 권한다. 시스템 보장값이 아니며 GPU가 통합 RAM 전체를 항상 할당받는 것도 아니다. 여기에 KV cache, recurrent state, 초안 모델/캐시, 동시 요청이 추가된다. swap으로 “로딩 성공”한 것을 쾌적한 추론으로 세면 안 된다.

Qwen3.5 9B config는 32층 중 full attention 8층, DeltaNet 24층이다. full attention KV heads 4개 × head_dim 256, FP16/BF16 KV 가정이면 2 × 8 × 4 × 256 × 2 bytes = 32 KiB/token. 이 부분만 8,192 tokens 약 256 MiB, 32,768 tokens 약 1 GiB다. recurrent state·초안 KV·workspace는 별도다. 전층 attention 공식을 그대로 적용하지 않았다. 실제 엔진 cache dtype/구현에 따라 달라진다. [4]

반면 Qwen3-32B의 64층/8 KV heads/128 head_dim FP16 KV는 약 256 KiB/token, 8K 약 2 GiB. Llama-3.3-70B의 80층은 약 320 KiB/token, 8K 약 2.5 GiB, 32K 약 10 GiB다. 컨텍스트는 입력뿐 아니라 생성·reasoning 토큰도 포함한다. 48GB에 39.7GB 가중치를 억지로 넣는 추천을 하지 않는 이유다. [12]

05 / M4 Max 속도는 얼마나 기대할까

실측이 아닌 단일 사용자·짧은 컨텍스트·4-bit 일반 생성 계획 범위다. speculation 이득은 포함하지 않는다. 대역폭/가중치의 거친 상한에서 KV·커널·연산·실효 대역폭 손실을 크게 할인했다. 아래보다 느릴 수도 있으며 구매 보증이나 합격선이 아니다.

예시410 GB/s546 GB/s읽기만 가정한 근사
9B · 본체 5.19GB25–5535–75약 79 / 105 tok/s

9B 계산은 원문 논리 비교용으로 본체만 썼지만 RAM은 약 6GB+캐시로 잡는다. 27B 카탈로그는 초안 등 포함 범위가 달라 계산부터 근사다. 숫자는 uzu M4 벤치마크가 아니다. 긴 입력 prefill, 32K 이상 KV, 동시 사용자, 한국어 토큰화, 발열·전원 모드, 양자화 커널 때문에 달라진다.

92.1 × 546 ÷ 153 ≈ 329는 채택하지 않는다. M5 int8 검증·수락률·트리 비용·커널 병렬성 및 M4의 현행 speculation 비활성화를 무시하기 때문이다. 128GB와 64GB는 같은 546GB/s 변형이므로 RAM 두 배가 생성 속도 두 배를 뜻하지 않는다.

06 / 지금 고른다면

  • 36GB: 9B부터. 27B는 4K–8K 컨텍스트와 앱을 줄인 조건에서 후보. 70B 제외.
  • 48GB: 27–32B가 유력한 절충. uzu 지원 27B와 별도 MLX 32B를 혼동하지 않는다.
  • 64GB: 70B 4-bit를 짧은 컨텍스트·저속 단일 사용자 용도로 검토. 고속 에이전트 전면 대체 보장 없음.
  • 128GB: 70B·긴 컨텍스트의 여유를 사는 선택. 9B만 쓴다면 추가 용량 가치가 작다.

실제 시험을 별도 승인한다면 RAM/GPU·macOS·엔진 commit·모델 revision을 고정한다. 일반 생성과 speculation 활성 여부를 로그로 분리하고 한국어 대화·코드·문서 요약을 같은 4K/8K 입력, 고정 256-token 출력으로 비교한다. 권장 sampling과 greedy를 별도 기록하고 cold/warm TTFT, decode, 전체 지연, peak RAM·memory pressure·swap, 수락률을 남긴다. 숨은 reasoning 길이도 통제한다.

코드 테스트·인용 근거·도구 JSON 의미로 품질을 채점한다. 모델의 262K context 설정이 내 Mac에서 그 길이까지 실용적이라는 뜻은 아니다. 이번에는 이 시험을 수행하지 않았다.

한 줄 결론

M4 Max는 9B~32B 로컬 활용의 진지한 후보이고 64/128GB라면 70B도 용량상 검토할 수 있다. 다만 현행 uzu 9B의 M5 중심 speculation 구성 때문에 “M4에서도 4배”라는 구매 논리는 성립하지 않는다.
