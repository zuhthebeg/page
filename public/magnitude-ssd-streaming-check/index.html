Magnitude,
“180B 모델을 64GB Mac에서”가 맞을까?

한 X 게시물은 오픈소스 추론 엔진 Magnitude가 SSD에서 MoE 전문가(expert)를 읽어 와서, M4 Max 64GB에서 Qwen 3.8 Flash Next(180B)를 2비트 양자화·64k 컨텍스트로 초당 56토큰에 돌린다고 소개한다. GitHub 저장소·공식 문서·벤치마크 페이지·모델 카드로 하나씩 대조했다.

작성·확인: 2026-11-26 · 원 게시물: 2026-11-25 · 문서·API 대조 / 직접 설치·실행 없음, 영상은 보지 않음

판정: 원리와 구조 숫자는 맞다. 다만 속도는 제작사 측정이고, “다 된다”가 아니라 SSD·메모리·양자화 품질이 결과를 정한다.

Magnitude는 Apache-2.0이고 Apple Silicon·NVIDIA·AMD·Intel·CPU를 지원한다고 문서가 밝힌다. Qwen3.8-Flash-Next는 총 180B, 활성 6B가 모델 카드와 일치한다. 공식 벤치마크 표에서 같은 모델이 Mac mini M5 Pro 48GB에 54 tok/s로 나와 56 tok/s는 그럴듯하다. 그러나 M4 Max 64GB는 공식 표에 없고, 모든 수치는 제작사가 자기 엔진으로 잰 값이며 모델 파일은 66GB다. 2비트급 양자화에서 답변 품질이 어떤지는 이 글이 확인하지 못했다.

1. 게시물 주장 대조

게시물 주장확인한 내용 / 판정
Qwen 3.8 Flash Next는 180B, 토큰당 약 6B 활성맞음. HF 카드: 125B(활성 6B) + n-gram 임베딩 51B + MTP 4B, safetensors 합계 179,999,981,459. 전문가 512개 중 라우팅 10개+공유 1개. “97%가 놀고 있다”는 6/180 계산이며, 총합에 포함된 51B 임베딩은 조회 테이블이라 MoE 층만 보면 약 95%다.
오픈소스, 무료, Apache 2.0맞음(엔진 기준). GitHub 저장소 라이선스 Apache-2.0. 단 모델은 별개다. Qwen3.8-Flash-Next는 HF 메타데이터상 qwen-community-1.0(“other”)이고, 이 글에서 약관 내용은 읽지 않았다. Magnitude 문서도 “모델 라이선스는 별도”라고 적는다.
M4 Max 64GB, 2비트, 64k, OpenCode에서 56 tok/s수치는 그럴듯, 직접 확인 불가. 영상은 보지 않았다. 공식 표의 Qwen 3.8 Flash Next(디스크 66GB, 64k 컨텍스트, 추측 디코딩 켬)는 M5 Pro 48GB 54, DGX Spark 83, RTX 5090+PCIe5 SSD 87, RTX 3090+PCIe4 41, RTX 3060 17, M2 Pro 32GB 13 tok/s. M4 Max 64GB 항목은 없다. 66GB÷180B ≈ 연 2.9비트로 “2비트 양자화”는 혼합 양자화로 읽힌다.
SSD는 읽기만 해서 마모 없음맞음(설계상). 문서: 스트리밍은 읽기 전용이라 플래시 마모가 없고 OS 스왑이 아니라 직접 비캐시 읽기를 쓴다. 모델 다운로드 시 한 번 쓰는 건 별개. 드라이버 쓰기량 논쟁은 지포스 SSD 쓰기 검증 참고.
오늘 출시표현 주의. 저장소는 2026-06-12에 만들어졌고 같은 날 알파 릴리스(0.0.1-alpha.15~17)가 있다. 11-24~26 사이 0.3.1~0.3.5가 매일 나왔다. “오늘 공개 런칭”일 수는 있어도 새 프로젝트는 아니다. 스타 약 8,800, 포크 640.
Apple·NVIDIA·AMD·Intel·CPU, 에이전트 원클릭 연결대체로 맞음. NVIDIA는 Ampere(RTX 30) 이상 CUDA, AMD·Intel은 Vulkan(ROCm 아님), Intel Mac은 CPU. Pi·OpenCode·Hermes·OpenClaw·Codex·Claude Code·Cline 연결 문서가 있다. Mac의 Docker는 GPU를 못 써서 CPU로 돈다.
양자화 이후 가장 큰 변화의견. 검증 대상이 아니다. 전문가 오프로딩 자체는 새 아이디어가 아니며, 이 엔진의 주장은 자동 튜닝·예측 프리페치로 실용 속도를 낸다는 것이다.

2. 왜 메모리보다 큰 모델이 도나

  • 희소 MoE: 토큰당 필요한 전문가는 일부다. 자주 쓰는 전문가와 공통 층은 GPU/통합 메모리, 다음 단계는 RAM, 나머지는 NVMe에 둔다.
  • 프리페치: README는 다음 토큰의 전문가를 예측해 SSD→RAM→VRAM으로 미리 올린다고 설명한다. 속도의 핵심이 이 예측 적중률이다.
  • 자동 튜닝: 모델 다운로드 때 최대 1분 동안 해당 칩에서 커널 설정을 시험하고, “모델 출력을 바꾸지 않는” 조합만 채택한다고 FAQ가 적는다. 공식 주장은 평균 Ollama 대비 2배 이상(제작사 측정).
  • 실전 제약: 컨텍스트가 메모리에 안 들어가면 2의 거듭제곱으로 줄여 제공하며 32K 아래로는 내리지 않는다. 앱 추천 속도는 “긴 에이전트 대화” 기준 추정치다.

읽는 법: 같은 모델이 장비에 따라 13~87 tok/s로 크게 갈린다. 메모리가 크고 SSD가 빠를수록 빠르다는 게시물의 결론과 일치한다. 반대로 32GB Mac이나 구형 PCIe 3.0 장비는 체감 속도가 훨씬 낮다. 표는 디코드 속도이고, 긴 입력을 읽는 프리필 속도·응답 품질은 위 발췌에 없다.

4. 한계와 주의

  • 독립 재현 없음: 벤치마크와 게시물 영상 모두 제작사·홍보 측 자료다. 직접 돌려 보지 않았다.
  • 양자화 품질: 평균 약 3비트로 줄인 180B가 원본 대비 얼마나 정확한지는 이 글 범위 밖이다. 속도와 별개로 코딩 에이전트 성공률을 따로 봐야 한다.
  • 모델 크기 요건: 모델 크기만큼 빈 디스크가 필요하다(여기서는 66GB). SSD가 느리면 속도가 직접 떨어진다.
  • 지원 계열 한정: 아무 GGUF나 되는 게 아니라 Magnitude가 커널을 만든 모델 계열만 지원한다.
  • 모델은 미리보기: 모델 카드는 이 모델을 Qwen4 아키텍처의 “실험적 미리보기”라고 설명한다.

5. 쓸 만한가

조건부로 시험할 가치가 있다. 64GB급 Mac이나 RAM 64GB+빠른 NVMe 장비에서 큰 MoE를 로컬로 돌려 보려는 사람에게 현실적인 선택지다. 반대로 메모리 32GB 이하, 느린 SSD, “클라우드 모델 수준 품질”을 기대하는 경우에는 맞지 않는다. 설치 전에 앱의 추천 화면(속도 추정)부터 확인하고, 본인 워크로드로 품질을 재 보는 편이 안전하다.
