Claude Code 코드모드,
토큰 효율이 정말 오를까?

Claude가 도구를 하나씩 부르는 대신 JavaScript 한 덩어리로 여러 도구를 호출하고, 필요한 결과만 돌려받는 실험 기능이다. “토큰이 크게 준다”는 말이 어디까지 사실인지, 그리고 우리가 쓰는 구성에서 쓸 수 있는지를 나눠 확인했다.

작성·확인: 2026-11-21 · Claude Code v2.1.323(2026-11-12) 기준 · 공식 문서 대조 + 독립 측정 인용 + 자체 1회 실측

판정: 실재하는 기능. 토큰 절감은 ‘조건부 가능성’ 수준이고, 대화형 터미널 밖에서는 쓸 수 없다.

공식 문서는 Code Mode를 실험적·기본 꺼짐·언제든 바뀌거나 제거될 수 있는 기능으로 설명하며 토큰 절감 수치를 제시하지 않는다. 독립 측정 1건은 입력 토큰 37.0% 감소와 처리 시간 15초→37초를 함께 보고했다. 또 -p, Agent SDK, VS Code 패널, Desktop, 클라우드 세션에서는 동작하지 않는다. 그래서 무인 자동 작업에 Claude Code의 이 기능을 그대로 붙일 수는 없다.

공식 문서 확인절감 수치는 독립 1회 측정속도는 느려질 수 있음
기능 식별 · 요구 조건 · 수치의 분모 · 우리 구성 실측 · 쓸 만한가 · 출처

1. 무엇이 추가됐나

공식 문서의 설명은 이렇다. 일반 세션은 Bash·Read·Edit 같은 도구 호출을 하나 요청하고 결과를 읽은 뒤 다음을 정한다. Code Mode에서는 Claude가 도구를 호출하는 JavaScript를 쓰고, Claude Code가 그 코드를 세션에서 실행한다. 한 코드가 명령을 병렬로 돌리고, 앞 결과를 다음 호출에 쓰고, Claude가 읽어야 할 부분만 반환한다.

  • 도입: v2.1.323(2026-11-12)에 실험적 opt-in으로 추가, v2.1.325(11-13)에서 첫날 버그 수정. 변경 이력은 이 글의 인용이며 changelog 원문을 직접 읽은 것은 아니다.
  • 켜는 법: 환경변수 CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1. 사용자 설정(~/.claude/settings.json)의 env에 넣으면 매 세션 적용된다. 프로젝트 설정 파일에서는 무시된다. 처음에는 확인 창에서 ‘Yes, turn on Code Mode’를 눌러야 한다.
  • 코드 보기: 대화에는 도구 호출 결과(예: 수정 diff)만 보이고, 코드는 Ctrl+O 전사 보기에서 접힌 Code 행으로 본다.
  • 권장 용도(공식): 여러 파일에 반복되는 변경, 결과를 걸러서 읽어야 하는 검색, 동시에 돌릴 수 있는 여러 명령.

3. “토큰이 줄어든다”의 분모

공식 문서에는 절감률이 없다. 널리 인용되는 수치는 출처가 서로 다르다.

  • 37%(API 쪽 수치): 2025-11 Anthropic의 Advanced tool use가 Programmatic Tool Calling에서 밝힌 43,588→27,297 토큰이다. Code Mode의 벤치마크가 아니다. joancomadran.dev가 이 점을 지적한다.
  • 독립 1회 측정: Wavect가 인용한 Juan Andrés Núñez의 쌍 비교는 Opus 5.5(중간 추론 강도)로 40개 JSON 주문 파일에서 상위 3명을 찾는 작업이다. 각 설정 1회 실행.
Claude Code 2.1.323, 40개 파일 질의 (Wavect 인용)
측정Code Mode 끔Code Mode 켬
입력 토큰(캐시 포함)150,36494,659
출력 토큰1,1721,213
모델 요청 수44
걸린 시간15초37초

입력은 55,705 토큰(37.0%) 줄고 두 설정이 같은 고객 3명을 찾았다. 같은 글은 일반 세션도 Python 스크립트를 쓸 수 있다는 점을 짚고, 차이의 상당 부분이 요청에 실리는 도구 설명이 작아진 것에서 왔다고 본다. 캐시 읽기와 새 입력은 가격이 다르므로 토큰 감소가 곧 비용 감소는 아니다. 77% 절감을 주장하는 보도도 있으나 1차 측정 출처를 확인하지 못해 인용하지 않았다.

읽는 법: “37% 감소”는 한 작업·한 모델·각 1회 실행의 값이다. “빨라진다”는 근거는 이 자료에 없고, 같은 측정에서는 오히려 2.5배 느렸다. 속도와 정확도는 직접 재 봐야 한다.

4. 우리 구성(OpenClaw)에서 직접 재 본 값

OpenClaw에는 이름이 같지만 별개 구현인 자체 코드모드가 있다. 모델이 보는 도구가 exec와 wait뿐이 되고, 나머지 도구는 숨겨진 목록에서 JavaScript로 찾아 호출한다. OpenClaw 문서도 이것이 Codex 코드모드와 다른 기능임을 명시한다. 다만 이 기능은 OpenClaw 내장 런타임에서만 작동한다. 우리 Claude 모델은 모두 claude-cli 런타임이고, OpenAI 기본 경로는 Codex 하니스라 지금 구성에서는 켜지는 모델이 없었다.

그래서 테스트용 qa 에이전트 하나만 Haiku 5.5를 내장 런타임 + 코드모드로 바꾸고, 다른 에이전트는 기존 claude-cli 경로로 두어 같은 읽기 전용 작업(파일 수·git 로그·파일 크기·체크박스 수를 확인)을 한 번씩 돌렸다.

Haiku 5.5, 동일 과제 각 1회, 4개 도구 호출 (자체 측정)
구성총 토큰(캐시 포함)시간
기존: claude-cli 런타임71,29220초
코드모드: 내장 런타임, 숨김 도구 41개19,1179초

답은 같았다. 4개 도구 호출이 코드 한 번으로 끝났다. 다만 이 비교는 코드모드 효과만 분리한 것이 아니다. 기존 경로는 Claude Code 하니스의 시스템 프롬프트와 모든 OpenClaw 도구 설명이 매 요청에 실리는 구조여서, 런타임 차이와 코드모드 차이가 섞여 있다. 표본도 각 1회, 도구 4번짜리 단순 작업이다. 긴 작업에서 속도와 정확도가 어떻게 되는지는 이 측정으로 알 수 없다.

5. 지금 쓸 만한가

  • 터미널에서 직접 Claude Code를 쓰는 사람: 여러 파일에 반복되는 변경이나 걸러서 읽는 검색이 많다면 시험해 볼 만하다. 업데이트 후 환경변수 하나로 켜고 끌 수 있다. 느려질 수 있고 자동 모드의 승인 의미가 코드 단위로 바뀐다는 점은 감수해야 한다.
  • 무인 자동화(-p·Agent SDK 기반): 공식 지원 대상이 아니다. 같은 효과를 원하면 OpenClaw처럼 별도 런타임의 코드모드나 도구 정의를 줄이는 방법을 따로 봐야 한다.
  • 측정 없이 켜지 말 것: 비용은 캐시 읽기와 재시도 포함 ‘정답 하나당 비용’으로 비교해야 한다.

이 페이지는 설치·장기 벤치마크를 수행하지 않았다. Claude Code 쪽 수치는 공식 문서 외에는 모두 2차 인용이다.
