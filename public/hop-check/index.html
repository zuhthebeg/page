HOP(Open HWP),
쓸 만한가

HOP은 한컴 없이 HWP/HWPX 문서를 열고 고치고 PDF로 뽑는 무료 오픈소스 데스크톱 앱이다. 랜딩 페이지가 말하는 것이 아니라 저장소, 릴리스, 열린 이슈에서 확인되는 것을 기준으로 어디까지 믿을 수 있는지 따져봤다. 직접 설치해서 문서를 돌려보지는 않았다.

점수는 "한컴이 없는 사람이 무료로 HWP를 다루는 도구로서" 기준이다. 열람과 변환만 보면 7점쯤, 중요한 문서를 편집하고 덮어쓰는 용도까지 포함하면 4점쯤이어서 중간인 6점으로 잡았다(평가).

1. 무엇인가

README는 HOP을 rhwp 위에 "얇게 껍데기를 씌운 앱"이라고 설명한다. 문서 파싱·렌더링·편집은 rhwp가 하고, HOP은 파일 열기, 저장, PDF 내보내기, 인쇄, 파일 연결 같은 OS 통합만 맡는다. 즉 HOP의 품질은 대부분 번들된 rhwp 버전이 결정한다.

2. 믿을 만한 부분

  • 초기 대응이 빨랐다. 메인테이너 코멘트에 따르면 v0.4.3에서 다크 테마와 검색 가능한 PDF 텍스트 레이어·한국어 폰트 번들을, v0.4.4에서 서식 도구 상자 깨짐을 고쳤다.
  • 저장 안전장치가 있다고 한다. 이슈 #73에서 메인테이너는 v0.4.0 예정 코드가 "임시 파일에 쓴 뒤 다시 파싱에 성공해야만 원본을 원자적으로 교체"한다고 답했다. 구조가 깨진 결과가 원본을 덮어쓰는 일은 막지만, 한컴에서의 의미적 손상까지 막는다는 뜻은 아니라고 본인이 선을 그었다. 이 동작은 직접 검증하지 못했다.
  • 엔진은 살아 있다. 엔진인 rhwp는 2026-10-06에 v0.8.7을 냈고, README는 외부 기여자 40명 이상과 공동 유지보수자 2명을 적고 있다.

3. 걸리는 부분

항목확인한 사실의미
엔진 버전 지연HOP v0.4.4는 rhwp 0.8.4. 업스트림은 0.8.6(09-02), 0.8.7(10-06)이미 고쳐진 버그를 그대로 안고 있음
표 마지막 줄 누락 (#99)셀 높이가 한 줄 모자라게 계산돼 화면·PDF·인쇄에서 마지막 줄이 사라진다는 보고. 파일에는 글자가 있고 rhwp 웹 데모·한글에서는 정상이라고 한다. 협력자는 관련 수정이 rhwp 0.8.6에 들어갔으나 같은 원인인지는 미확인이라고 답했다그대로 제출하면 글자가 빠진 PDF가 나갈 수 있음
저장 호환 (#73)0.3.1에서 원본 HWP를 열어 저장하면 한컴이 파일을 못 연다는 보고. 메인테이너는 재현용 최소 파일을 요청했고 이슈는 열려 있다최신 버전에서의 재현 여부는 불명
p 키 입력 불가 (#95·#100)영문 p/P가 입력되지 않음. 개체 속성 단축키가 키를 소비하던 문제로, rhwp 0.8.6에서 수정. 수정 PR #101은 미병합영문을 쓰는 문서에선 치명적일 수 있음
암호 문서 (#98)Linux에서 암호 걸린 HWP를 열면 비밀번호 입력창 없이 오류만 뜬다암호 문서는 다른 도구 필요
그 밖새 창 복사 시 레이아웃 깨짐(#96), 인쇄 시 표 안 글자 누락(#78)·레이아웃 깨짐(#70), macOS v0.4.1 서명 검증 실패 보고(#89), Windows ARM64 빌드 없음(#80)모두 열린 상태
HWPX 저장README의 저장 항목은 "HWP 문서"만 적혀 있다. HWPX 저장 가능 여부는 확인하지 못했다HWPX 편집은 미확인
유지보수마지막 공개 커밋 08-28. 이슈 #95·#99에 답한 것은 메인테이너가 아니라 외부 협력자다당분간 업데이트를 기대하기 어렵다

이 목록의 상당수는 HOP이 아니라 rhwp 쪽 문제를 번들 버전이 못 따라간 결과다. 반대로 말하면 HOP은 업스트림이 고친 것을 곧바로 받지 못하는 구조이고, 메인테이너가 움직이지 않는 동안에는 사용자가 고칠 방법이 없다.

4. 용도별 판정

용도판정
받은 HWP 열어보기쓸 만함 표가 많은 문서는 한컴이나 rhwp 웹 데모와 한 번 대조
HWP를 PDF로 변환조건부 #99 때문에 표 있는 문서는 결과 PDF의 셀 마지막 줄을 눈으로 확인
가벼운 수정 후 다른 이름으로 저장조건부 저장본을 한컴에서 열어 확인
제출·계약 문서를 덮어쓰기 저장비권장
한컴 없이 Mac·Linux에서 HWP를 가끔 볼 때가장 현실적인 무료 선택지 중 하나
암호 문서, HWPX 편집, ARM64 Windows지원이 불확실하거나 없음

5. 쓴다면 이렇게

  • 원본을 따로 두고 항상 다른 이름으로 저장한다.
  • 저장본과 PDF를 한컴 또는 rhwp 웹 데모로 열어 대조한다. 표가 있으면 셀 마지막 줄부터 본다.
  • Windows·Linux라면 HOP 코드에서 출발했다는 포크 알한글(Alhangeul)도 비교 대상이다. 개발자 본인 소개로는 rhwp 0.8.6 기반이고 v0.1.1이 최신이며, 이 수치와 "관련 수정 포함" 주장은 직접 검증하지 못했다. Windows 설치 파일은 서명이 없다고 스스로 밝히고 있다.
  • 업스트림의 rhwp 웹 데모는 설치 없이 같은 엔진의 최신판을 볼 수 있어, 문제가 HOP 문제인지 엔진 문제인지 가릴 때 쓸 수 있다.

결론

HOP은 "한컴 없이 HWP를 연다"는 목적에는 이미 충분하다. 약점은 앱 자체보다, 엔진 업데이트를 따라가지 못하는 현재의 유지보수 상태와 아직 열려 있는 표 렌더링·저장 호환 이슈다. 열람과 PDF 변환은 결과를 한 번 확인하는 조건으로 쓰고, 중요한 문서의 편집과 덮어쓰기는 한컴으로 하는 것이 안전하다. 새 릴리스가 rhwp 0.8.7 이상으로 올라오고 #99·#73이 닫히면 점수를 다시 올릴 수 있다.
