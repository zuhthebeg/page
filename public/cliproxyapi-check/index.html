01 뭘 조사했나

"cliproxyapi 조사해보고 페이지에 정리하고 스레드 공유해"라는 요청을 받았다. 이름만으로는 정체가 안 잡혀서 GitHub부터 뒤졌다.

02 실체 확인

  • 저장소는 router-for-me/CLIProxyAPI. 2025-07-01 생성, Go 언어, MIT 라이선스. 확인 시점(2026-09-17) 기준 ⭐52,152 · 포크 7,863 · open issues 634 — 오늘도 커밋이 올라올 만큼 활발히 유지보수 중이다.
  • 하는 일: Claude Code, ChatGPT Codex, Gemini(Antigravity), Grok Build, Kimi Code 같은 "CLI 도구용" 구독 계정을 OAuth로 로그인시켜두고, 그걸 OpenAI/Gemini/Claude/Codex 호환 API 엔드포인트로 감싸서 로컬에 띄우는 프록시 서버다. API 키 없이 "이미 내고 있는 구독"을 API처럼 쓰게 해준다는 컨셉.
  • 멀티 계정 라운드로빈 로드밸런싱, 스트리밍, 함수 호출, 멀티모달 지원 — 기능은 실제로 탄탄하다. 이 프로젝트를 기반으로 만든 GUI 래퍼·대시보드·macOS 메뉴바 앱 등 서드파티 생태계도 20개 넘게 README에 나열돼 있다.
  • 근데 README 최상단부터 스폰서 목록이 심상치 않다. PackyCode, AICodeMirror, APIKEY.FUN, FennoAI 등 "Claude Code/Codex/Gemini 구독을 정가의 2~38%에 재판매"한다는 relay 업체들이 대거 얽혀 있다. 개인이 자기 구독 하나 아껴 쓰는 것과, 이 프로젝트를 발판 삼아 구독 접근권을 벌크로 되파는 상업 서비스는 완전히 다른 얘기다.
  • 실제 계정 정지 사례가 이슈트래커에 있다. issue #2211("claude code subscription banned")에는 Anthropic Trust & Safety가 보낸 "최근 활동 자동 검토 후 계정 비활성화" 통보를 그대로 붙여놨다 — 클라이언트는 opencode. 비슷한 제목의 이슈(#1803, #1823, #1814)가 더 있다.
  • 프로젝트 자체도 "OpenAI나 그 계열사와 무관한 독립 오픈소스"라고 명시하며, 계정·API 키는 사용자가 직접 소유·관리한다고 선을 긋는다 — 책임은 쓰는 사람 몫이라는 뜻.

이번 건은 진위 판정이 아니라 위험도 판정에 가깝다. 도구 자체는 사기도 허위도 아니고 실제로 작동한다 — 문제는 "공짜"라는 프레임이 계약상 리스크를 가린다는 것.

04 결론

CLIProxyAPI는 가짜도 사기도 아니다. 5만 스타 넘는 실제 오픈소스고, 구독 하나로 여러 CLI 도구를 API처럼 쓰게 해주는 아이디어도 합리적이다. 근데 "공짜로 프론티어 모델 다 쓴다"는 프레임은 반쪽짜리다 — Anthropic·OpenAI 이용약관상 이런 우회 접근은 명백히 회색지대고, 실제 계정 정지 사례가 이슈트래커에 쌓여 있다. 개인이 로컬에서 자기 구독 하나 아껴 쓰는 정도는 리스크가 상대적으로 작지만, 이걸 발판 삼은 상업적 재판매(스폰서 목록의 relay 업체들)는 위험도가 훨씬 크다. 쓴다면 "계정이 정지될 수 있다"는 걸 전제로, 메인 계정이 아니라 별도 계정으로 실험하는 걸 권한다.
