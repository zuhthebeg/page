03 / RTX 3080 Ti 12GB라면

지금의 실용 판정은 “권리 확인 후 제한된 파일럿 후보”다. GPU가 있다는 이유로 설치를 권하지 않는다. 한국 제외 조건이 먼저이고, 기술적으로도 텍스트 인코더를 GPU에 상주시키기 어렵다. 예시 Q4 인코더는 파일만 13.58GiB여서 12GB 카드보다 크다.

예산은 단계별로 계산한다

텍스트·참조 인코딩 → 인코더 오프로딩 → DiT 샘플링 → DiT 오프로딩 → VAE 디코딩. 단계별 peak는 그 단계의 가중치 + 활성값 + attention/workspace + 역양자화 버퍼 + 런타임·화면 사용량이다. CPU로 내린 가중치와 로딩 버퍼는 시스템 RAM을 쓴다. 파일 합계만 더하거나 가장 작은 파일만 보는 계산은 둘 다 틀릴 수 있다.

  • Q2: DiT 파일 약 6.40GiB라 12GB에서 오프로딩을 검토할 여지는 있다. 그러나 4K·참조 이미지·VAE 디코딩 peak는 별도여서 적합 판정으로 확정하지 않는다.
  • Q3: DiT 약 8.30GiB. Q2보다 가중치 여유가 줄고, 품질 향상 폭은 미측정이다.
  • Q4: DiT만 약 10.78GiB. 디스플레이·활성값 등을 남기면 전체 GPU 상주를 기대하기 빠듯하다. “12GB용 추천”이라고 단정하지 않는다.
  • 8GB 카드: Q2 배포자의 권장표 외에 이 조사에서 재현 가능한 4096² peak·시간 측정을 확보하지 못했다. 불가능을 증명한 것도 아니고, 실용을 검증한 것도 아니다.

4K와 16개 참조는 가장 나중에

공식은 약 4–20MP 범위, 약 16MP에서 좋은 결과를 안내한다. 4096²는 2048²의 픽셀 수 4배지만 전체 메모리·시간이 정확히 4배라는 뜻은 아니다. 참조 이미지 수·해상도도 토큰과 VAE 작업을 늘린다. 작은 시험 해상도를 낮춰도 일부 서버는 min_generation_area 기본 4MP로 내부 생성 후 축소하므로 출력 크기만 보지 말아야 한다. 공식 Comfy 문서는 4MP 시작을 안내하지만, 조회한 JSON 내부 conditioning 위젯에는 3104×3104 값도 있어 가져온 그래프의 실제 활성 해상도를 확인해야 한다. [2][4][6]

얇은 Mac의 통합 RAM은 “VRAM 8GB”가 아니다

Mac은 CPU·GPU·OS가 같은 메모리 풀을 공유한다. 8GB 통합 RAM에 6.4GiB DiT만 놓는 식의 추천은 인코더·VAE·OS를 빼먹는다. 16GB도 이 예시 세 파일의 동시 상주는 용량부터 맞지 않는다. 큰 RAM의 Mac 역시 Apple Silicon/MPS·MLX 런타임의 해당 아키텍처와 양자화 지원을 따로 확인해야 한다. CUDA GGUF 사례를 Mac 실행 증거로 쓰지 않는다. 칩·RAM·backend별 실측이 없으므로 초 단위 속도나 최소 RAM을 제시하지 않는다.

04 / “최신 ComfyUI+GGUF”에도 확인문이 붙는다

공식 Comfy 문서는 ComfyUI 0.45.0+ / template pack 0.11.104+를 요구한다. 조사 시점 최신 안정 릴리스는 v0.45.0(11월 10일). T2I와 Edit 템플릿은 core의 MiniMaxH3ImageConditioning, 전용 이미지 VAE와 Qwen3-VL 인코더를 사용한다. 일반 SD VAE나 H3 영상 VAE로 바꾸는 조합이 아니다. [4][6]

6스텝은 별도 “Turbo”를 더 찾으라는 뜻이 아니다. 공식 MiniMax-H3-Image가 이미 6-step PDD 증류판이다. 원래 H3 영상 모델·다른 파생판과 구분한다. 공식 서버는 steps를 생략하거나 6, guidance를 생략하거나 1로 쓰며 다른 값은 HTTP 400으로 명시한다. Comfy 템플릿은 euler / simple / steps 6 / CFG 1 / denoise 1. no CFG는 추가 unconditional 패스가 없다는 뜻이고 negative prompt는 지원하지 않는다. 20·30스텝을 넣으면 더 좋아진다는 일반 SD 습관을 적용하지 않는다. [2][6]

GGUF 즉시 호환은 아직 확인 게이트다.

Abiray 카드는 embedded config / pdd_sigmas 덕분에 stock GGUF 노드에서 패치 없이 된다고 주장한다. 조회한 city96 commit 6ea2651은 metadata 전달을 구현하지만, 이미지 아키텍처 허용 목록과 변환 감지 목록에 MiniMax H3 이름이 없었다. core의 H3-Image 인식과 GGUF loader의 통과는 다른 문제다. 파일 헤더·실제 로딩을 검사하지 않았으므로 이 조합을 “검증된 무패치 실행”으로 소개하지 않는다. 이것만으로 모든 GGUF 포크·파일의 실행 불가를 단정하지도 않는다. [7]

확인할 조합은 core 버전 + GGUF 노드 commit + DiT 파일 revision/metadata + 텍스트 인코더 loader + VAE + 워크플로 전체다. 배포자가 남겨둔 fallback Python 패치도 단순 데이터가 아닌 실행 코드다. 이 조사에서는 설치하거나 실행하지 않았다.

프롬프트 확장기(PE)와 필수 텍스트 인코더는 별개다. 공식 PE는 17.9GB NVFP4, Comfy 템플릿은 더 가벼운 Qwen3.5 9B W4A8 대안을 쓰며 T2I는 기본 꺼짐, Edit는 켜짐이라고 문서화했다. PE를 끄더라도 Qwen3-VL 인코더가 없어지는 것은 아니다. RTX 3080 Ti는 Blackwell이 아니므로 NVFP4 파일이 보인다고 해당 전용 가속 경로를 쓸 수 있다고 가정하지 않는다. 실제 지원 커널·대체 정밀도는 별도 검증 대상이다. [2][4]

품질·기능의 알려진 경계

  • 공식은 상세한 영어 전체 장면 설명을 기대한다. 한국어 직접 입력·한글 타이포 정확도는 이 조사에서 시험하지 않았다.
  • Q2의 문자·손·재질·정체성 보존 및 16개 참조 일관성은 별도 비교가 필요하다. 해상도가 높아도 사실 정확성이나 편집 보존이 보장되지 않는다.
  • 공식 API 사양은 mask inpainting·투명 배경·사용자 지정 seed·preview 미지원을 적는다. 이것은 호스팅 API 사양이며 seed를 받는 로컬 예제·Comfy sampler까지 seed 불가로 확대하지 않는다. [8]

05 / 한국에서는 라이선스가 첫 번째 문턱

2026-11-10자 MiniMax-H3-Image Community License Agreement는 Apache/MIT가 아니다. Section I.5는 제외 지역으로 EU·영국·대한민국·미국을 명시한다. Section II는 권리를 Applicable Territory 안에서만 부여하고, V.4는 그 밖의 모델·출력 사용 등을 허용하지 않는다고 쓴다. 한국 개인용·연구용이어서 자동 면제라는 조항은 확인하지 못했다. 별도 허가 여부는 MiniMax에 확인해야 한다. 법률 자문은 아니다. [9]

“Excluded Territories” means the European Union, the United Kingdom, the Republic of Korea and the United States of America.
  • 상업용: 적용 지역 안에서도 본인/계열사 Annualized Revenue가 미화 100만 달러를 초과하거나, 제3자에게 Hosted Service를 제공하면 사전 서면 허가가 필요하다. API만 아니라 웹 접근 등도 정의에 포함된다. 상업 제품·서비스 UI에는 모델명 표시 의무도 있다.
  • 재배포: 라이선스 사본, 수정 고지, 해당 NOTICE 등과 지역·AUP 조건이 있다. GGUF로 바꿨다고 원본 조건이 사라지지 않는다.
  • 다른 AI 학습: V.3은 모델 또는 출력을 다른 AI 개선에 쓰는 것을 제한한다(이 모델과 그 파생모델은 예외). “이미지 출력은 내 것”이라는 설명과 “아무 모델 학습에나 사용 가능”은 다른 주장이다.
  • 산출물: MiniMax는 출력에 대한 권리를 주장하지 않는다고 쓰지만, 제3자 저작권·초상권·상표와 AUP 책임은 사용자에게 남는다. 공개 출력의 AI 생성 표시 조건도 읽어야 한다.

ComfyUI 엔진은 GPLv3, city96 GGUF 노드는 Apache-2.0이다. 엔진의 오픈소스 라이선스가 모델의 지역·상업·학습 제한을 덮지 않는다. 이 Image 모델 조건을 이전 H3 영상 모델의 조건과 혼동하지 않는다. [7][9]

무료 가중치 ≠ 비용 없음, 로컬 UI ≠ 로컬 처리

자체 로컬 추론은 GPU·RAM·디스크·전력·설정 시간의 비용을 쓴다. 클라우드 GPU·공식 API·Context-IR 프롬프트 확장은 별도 요금·서비스 약관 대상일 수 있어 현재 요금표를 확인해야 한다. 이 글은 가격을 고정하거나 무료 API를 보장하지 않는다.

공식 “Full Workflow” 예제는 로컬 이미지 생성 앞에서 MiniMax Context-IR API와 API key를 사용하는 경로를 제시한다. 그 경로에서는 프롬프트와 편집용 참조 이미지가 외부로 전송될 수 있다. 로컬 PE 대안도 문서에 있으나 추가 모델과 자원이 필요하다. 완전 로컬 그래프인지 노드·endpoint를 확인하기 전에는 민감한 얼굴·고객 자료를 넣지 않는다. 이 조사에서는 입력을 API로 보내지 않았다. 이 글 자체는 기존 사이트의 GTM 분석을 사용한다. [2]

06 / 실행을 결정하기 전 체크리스트

  1. 권리부터: 한국에서 쓸 수 있는 별도 허가와 상업·호스팅 범위를 확보한다. 미확인 상태면 실행 단계로 가지 않는다.
  2. 조합 고정: core·template pack·GGUF 노드·파일 revision과 PDD metadata 호환을 확인한다. 24채널 이미지 VAE·인코더 종류를 맞춘다.
  3. RAM과 디스크: 필수 동반 파일, CPU 오프로딩 RAM, OS·브라우저·로딩 버퍼·캐시를 모두 남긴다. 실제 RAM 용량이 확인되지 않아 이번 글은 최소 RAM을 보증하지 않는다.
  4. 조건부 첫 시험: 허가 후 별도 시험한다면 T2I·batch 1·참조 없음·PE 꺼짐·실제 내부 4MP·steps 6·CFG 1부터. 이것도 성공이 검증된 설정은 아니다. 성공 후 단일 참조 편집, 마지막에 16MP로 올린다.
  5. 메모리와 시간 분리: 인코딩·샘플링·VAE별 peak VRAM/RAM, swap, cold/warm 전체 지연, 실패·재시도 횟수를 기록한다. “파일 로드 성공”을 4K 실사용 성공으로 세지 않는다.
  6. 고정 품질 세트: 영어 장면, 한글 간판, 작은 영문, 손·다중 인물, 단일 참조 보존 편집을 Q2/Q3/Q4에 같은 seed·프롬프트로 비교한다. 이 수용 시험은 아직 실행하지 않았다.
결론

관심을 가질 만한 네이티브 고해상도 이미지 모델이다. 다만 6.4GiB는 pruned DiT의 디스크 크기이고, RTX 3080 Ti의 4K 생성 시간이나 전체 VRAM 요구량이 아니다. 한국 사용자에게 지금 필요한 것은 “일단 설치”가 아니라 이용 허가 → loader 호환 → 단계별 메모리·품질 측정 순서다.
