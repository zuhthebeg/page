02 / 설치 경로와 “무료”의 범위

Codex 네이티브 플러그인

공식 Codex 문서는 Codex 0.146.0 이상에서 마켓플레이스 등록 → ecc@ecc 플러그인 추가 → 등록 확인 → Codex 재시작을 안내한다. 이후 /hooks에서 훅 정의를 별도 검토·신뢰해야 한다. 이전 legacy sync로 홈 디렉터리에 파일을 복사하는 방식과 섞지 말라고 명시한다.

가격·권한

저장소 MIT; OSS 도구 사용 자체는 무료다. 다만 모델 사용량·연결 서비스 비용은 별개. ECC Tools GitHub App 가격표는 공개 저장소 분석 Free 월 10회(1회 최대 200커밋), 비공개 저장소 Pro 월 $19/활성 개발자 좌석부터로 구분한다. OSS 플러그인과 유료 호스팅 앱을 동일 상품으로 혼동하지 말 것.

공식 Codex 문서에는 네이티브 플러그인 설명의 “281 skills”처럼 현재 트리 311개와 어긋난 고정 숫자도 남아 있다. 한국어 README에는 더 오래된 140K+ 스타·16 에이전트·65 스킬 표기가 섞여 있다. 설치 안내·숫자는 번역 문서보다 현재 main 트리와 최신 Codex 전용 문서를 우선해야 한다.

권한 경계: 스킬은 모델에 읽히는 지시문이고, 훅은 명령 실행을 수반할 수 있다. 외부 저장소를 읽고 전역 설치하라는 원문의 프롬프트를 그대로 실행하지 말고, 실제 경로·기존 설정·MCP·훅을 검토한 뒤 격리 프로젝트에서 최소 권한으로 시험한다. 이 글은 설치를 권고하는 명령 수행 보고서가 아니다.

03 / cocy.io·OpenClaw에 쓸모 있나?

우리 평가는 “방법론은 유용, 패키지 통째 이식은 비추천”. 이미 OpenClaw에는 스킬, 하위 에이전트, 검증·디버깅·메모리 워크플로가 있다. ECC의 Codex 전용 플러그인이 OpenClaw에 그대로 설치된다는 근거는 없다. 중복 311개를 더하면 탐색 비용과 충돌 면적이 늘 수 있다.

  1. 쓸모 있는 부분: 리서치 우선, 작은 검증 루프, 코드 리뷰 기준, 훅 안전성 점검 같은 몇 가지 문서를 현재 프로젝트 관례와 대조해 골라 참고한다.
  2. 하지 않을 것: 사용자 홈·OpenClaw 설정에 자동 설치, 전체 훅 허용, 기존 메모리·스킬을 덮는 전역 동기화. 소스 검토 없이 외부 플러그인에 비밀·권한을 넘기지 않는다.
  3. RTX 3080 Ti 12GB와 WSL: ECC는 로컬 모델 가중치가 아닌 에이전트 작업흐름/설정 저장소라 GPU 메모리 이점이 직접 생기지 않는다. 실제 작업 비용은 연결된 Codex 모델 호출과 도구 실행에 좌우된다.

검토를 시작한다면 Codex를 실제 사용하는 별도 실험 저장소에서 한 스킬을 골라 기존 워크플로와 같은 과제·테스트·토큰 사용량을 비교하자. 이번 평점은 문서·구조 조사 기준이며 생산성 실측 평가가 아니다.
