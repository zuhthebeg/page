Ollaya는 로컬 Jev일까?

정확히는 Jev와 비슷한 요청 형식으로 오픈 판단 모델을 실행하는 도구다. API가 같아져도 판단력이 같아지는 건 아니다. GeekNews 글을 계기로 1차 출처를 확인했다.
소스·릴리스·장비 사양 확인 / 설치·실사용 벤치마크는 하지 않음
VERDICT / 사실인 것과 아직 아닌 것
로컬 판단 모델을 갈아 끼우는 인프라로는 흥미롭다.
한국어 자동 위임의 정답이라고 홍보하진 않겠다.

런타임은 Apache-2.0이고 TypeSafe 형식 엔드포인트·MCP를 문서화했다. 그러나 Jev 원본 가중치가 아니며, 정확도·속도는 선택한 모델과 우리 데이터에서 따로 검증해야 한다.

공식 GitHub 저장소는 Rust 기반 서버·CLI·런타임 코드를 공개하고 있다. v0.7.0 릴리스에는 플랫폼별 실행 파일이 있다. 공식 호환성 문서에는 POST /v1/systemone, GET /v1/models, Python SDK 0.7.1 대상 요청·응답 계약이 명시돼 있다. 이 호환성은 프로젝트가 제시한 계약이지, 우리가 모든 SDK 호출을 시험한 독립 검증은 아니다.

CLI와 별도로 MCP 서버·에이전트 스킬도 제공한다. 이들은 모델을 호출하기 쉽게 해주는 접점이다. 스킬을 설치했다고 OpenClaw의 모델 라우팅 정책이 자동으로 바뀌지는 않는다.

02 / BOUNDARY

같은 API ≠ 같은 모델

Ollaya가 해결하는 일

오픈웨이트 Laya·decider·NLI·GLiClass·Kev 등 여러 판단 모델을 로컬 HTTP/MCP 뒤에 두고 이름으로 관리한다. 모델별 서버 코드를 직접 다루는 수고를 줄일 수 있다.

해결하지 않는 일

TypeSafe의 Jev 원본 가중치·판단 정확도는 제공하지 않는다. 분류 기준, 이전 대화 맥락, 위임 실패 비용은 여전히 우리 앱이 설계·측정해야 한다.

공식 호환성 문서도 모델 품질이 Jev와 과제별로 다르며 자체 데이터로 측정하라고 명시한다. 예를 들어 문서의 Banking77 수치 비교는 제작자 제공/인용 수치로, 우리 한국어 업무나 RTX 3080 Ti 성능을 입증하지 않는다. “5개 질문 Laya 8~10ms”는 제작자의 RTX 4090 측정이다. Jev 호스팅 API 지연과 같은 조건의 대조군도 아니다.

이전 자체 실험과 연결: 실제 한국어 대화 147건에서는 Laya의 맥락 포함 라우팅 정확도가 24.5~34%, Jev-Style v3가 49.0~51.7%, 단순 규칙+이전 작업 유지가 76.2%였다. 이 수치는 단일 사용자·단일 라벨러의 탐색 결과이며 Ollaya로 다시 측정한 값이 아니다. 런타임을 바꾼다고 모델 판단 자체가 갑자기 Jev 수준이 되진 않는다. 실험 방법·한계 보기 ↗

03 / FIT

우리 3080 Ti에서는?

공식 FAQ의 CUDA 경로는 Linux/WSL 2/Windows x86-64에서 NVIDIA 드라이버 R580+를 요구한다. 현재 로컬 장비에서 확인한 드라이버는 591.86, VRAM은 12GB, WSL Debian 13의 glibc는 2.41로 문서 최소치(glibc 2.38)를 넘는다. 요구조건을 충족한다는 것과 설치·추론 성공은 다르다. 이번 조사에서 설치 프로그램을 실행하거나 모델을 다운로드하지 않았다.

가치 있는 후속 실험은 설치 자체가 아니라 같은 147건에 다른 모델(decider, NLI, Kev)을 넣어 규칙 기준선과 비교하는 것이다. 원문·정답은 로컬에만 두고, 후보 순서를 바꿨을 때의 일치율과 “무거운 일을 싼 모델로 오분류”한 횟수를 함께 재야 한다. GPU 메모리·첫 호출 지연과 프로세스 안정성도 기록한다.

04 / DECISION

결제 대신 시험할 순 있다. 단, 안전하게

  1. 후보는 제한적으로. 속도 광고나 벤치마크 순위만으로 자동 위임하지 말고, 각 모델을 고정된 과제에 시험한다.
  2. 비공개 샘플을 격리. 로컬 서버의 실제 바인딩·로그 정책을 확인하고 외부 API 전송 없이 평가한다. 공식의 “상태를 기록하지 않는다”는 설명은 제작자 진술이며 우리 환경에서 아직 검증하지 않았다.
  3. 먼저 조언 모드. 누락·오분류가 낮고 비용/완료율이 좋아졌을 때만 자동화를 검토한다. 애매한 경우 기존 강한 모델을 유지한다.

프로젝트가 공개된 지 며칠 안 된 신생 런타임이라는 점도 운영 리스크다. 기본 로컬 API를 공용망에 노출하지 말고, 신규 설치 스크립트는 검토 후 실행하는 편이 맞다.
