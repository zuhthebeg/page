Raw-RAG, 복잡한 에이전트 메모리를 정말 이겼나?

원본 대화를 잘 검색하는 것만으로도 강한 메모리 시스템을 만들 수 있다. 다만 X에서 퍼진 ‘83배’는 챗봇 응답 속도가 아니라 특정 비교에서 대화를 메모리에 넣는 시간이다.

2026-11-28 · arXiv 프리프린트 v1과 원 게시물 대조 · 독립 재실험 없음

판정: 7개 설정 중 6개에서 비교한 메모리 시스템 중 1위. 모든 조건에서 최고는 아니며, ‘83배 빠른 응답’은 논문 결과가 아니다.

1. ‘단순 RAG’도 검색은 공들였다

대화를 256토큰씩, 32토큰을 겹쳐 자른 뒤 평면 벡터 인덱스에 저장한다. 질문과 가까운 128개 후보를 찾고, 질문과 후보를 함께 읽는 교차 인코더로 재정렬해 15개를 고른다. 원문을 요약이나 지식 그래프로 바꾸지 않았다는 뜻이지, 벡터 검색 한 번으로 끝난다는 뜻은 아니다. MemoryAgentBench의 GPT‑4o‑mini 실험에서는 재정렬을 빼자 종합 점수가 48.32에서 44.40으로 떨어졌다.

논문 §3: 검색 설계 · §4.3: 구성요소 제거 실험

2. 무엇을 이겼고, 어디서 졌나

논문의 6/7은 LoCoMo·LongMemEval·MEME·MemoryAgentBench에서 모델을 달리한 일곱 설정을 세고, 전체 대화를 통째로 넣는 Full-context는 순위에서 제외한 값이다. LongMemEval의 표에서는 Raw-RAG 87.53, Memora 87.40으로 차이가 0.13점뿐이다. 반대로 MEME에서 DeepSeek‑V4‑Flash를 쓸 때는 Raw-RAG 43.19로 MemMachine 44.71에 뒤졌고, 같은 표의 Full-context는 63.17이었다.

논문 §4.2: 표 3·4

3. 83배는 어떤 시간인가

거의 100만 토큰인 BEAM-1M 대화 한 건(1,710개 메시지)을 순차적으로 넣은 실험이다. 논문 본문 표기 기준 Raw-RAG는 0.33시간(약 20분), Memora는 26.95시간, 완주한 시스템 중 차순위 MemOS는 3.25시간이었다. 반올림된 본문 값끼리 나누면 각각 약 82배, 약 10배 차이다. X의 83배는 첫 비교의 규모와 비슷하지만 18분(0.3시간)을 그대로 넣으면 83배가 되지 않는다.

답변 생성과 채점은 제외됐다. 별도 MemoryAgentBench 실험에서도 Raw-RAG는 저장과 검색을 합친 총시간은 더 짧았지만, 검색 단계만 보면 255.59초로 Mem0의 117.72초보다 길었다. 따라서 ‘83배 빠른 검색’도, ‘83배 빠른 응답’도 아니다.

논문 그림 1 · 부록 D.6: 측정 범위

4. 업데이트와 삭제는 쓸모없다는 뜻인가

연구진은 Mem0의 쓰기 결정 462,760건을 분석했다. 실제 저장 텍스트를 바꾸거나 지운 비율은 LoCoMo 1.90%, LongMemEval 1.34%였다. 별도 LoCoMo 실험에서는 업데이트를 추가로, 삭제를 무동작으로 바꾸자 67.36%에서 69.42%로 올랐다. 이 구성에서는 이득이 없었다는 뜻이지, 모든 시스템에서 갱신이 해롭다는 뜻은 아니다. 특히 개인정보 삭제 요청이나 보존 기간 정책은 정답률과 별개의 요구사항이다.

실무에서는

원본을 보관할 권한이 있는 데이터라면, 먼저 원본 검색 + 재정렬을 기준선으로 재는 게 합리적이다. 요약은 빠른 탐색에 쓰되, 날짜·예외·결정 근거가 중요한 질문에서는 원문을 다시 찾게 하자. 이 논문은 공개 오프라인 대화 벤치마크 결과다. 실시간 대화, 장기 저장 비용, 개인정보 삭제, 우리 시스템의 속도까지 입증한 것은 아니다. Raw-RAG의 공식 구현 공개나 코드 라이선스는 확인하지 못했다.
