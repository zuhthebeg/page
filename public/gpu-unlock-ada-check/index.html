01 원문과 실체

@NFT_Chen의 2026-10-24 게시물은 4090 165→331 TFLOPS, 4080 SUPER 1.83배, 4070 Ti SUPER 2배, 4060 Ti 약 40%를 주장한다. Linux gpu-unlock-ada와 Windows AD103_win_unlocker를 연결했다.

실체 확인: Ada 저장소는 2026-10-23 생성된 GPL-2.0 소스 프로젝트다(확인 당시 별 1,011개·공개 이슈 9개). 기반인 Zagitta/gpu-unlock은 2026-10-18 생성된 30 시리즈용 선행 구현이며 README에 3090 Ti BF16 GEMM 87.5→157.4 TFLOPS 등 사용자 보고를 정리한다. 둘 다 새 프로젝트라 장기간 안전성 근거는 없다.

02 무엇을 바꾸나

BIOS 이미지나 NVIDIA 드라이버 파일은 패치하지 않는다. 하지만 “소프트웨어 설정만 변경”도 아니다. Linux 커널 모듈이 NVIDIA 드라이버보다 먼저 실행되고, 서명된 GPU 펌웨어의 기존 코드 흐름을 이용해 보호된 레지스터 쓰기 권한을 얻은 뒤 BAR0 MMIO에서 FEAT PLM 0x00823804, 속도 선택기 SS0 0x0082381c·SS1 0x00823820을 조작한다. SS0=0x88888888, SS1=0x8을 읽어 확인하고 PCIe FLR 후 원래 드라이버로 넘긴다. OTP 퓨즈를 다시 굽는 방식은 아니다. 근거는 4090 레지스터 보고서와 HF의 디스어셈블리 분석; NVIDIA 공식 지원 기능이라는 뜻은 아니다.

03 165→331은 착시인가

이번 경우 FP16 누적을 FP32 누적으로 바꿔 적은 착시는 아니다. 벤치 소스는 입력과 누적 타입을 별도 템플릿 인자로 지정한다. 검증 GEMM도 CUDA_R_32F 출력·CUBLAS_COMPUTE_32F를 쓴다. 4090 원 실험은 FP16/FP32 165.6→331.6, BF16/FP32 165.5→330.6 TF/s이며 FP16/FP16 대조군은 원래 약 326~332 TF/s다. 공식 4090 Ada 스펙의 FP16 텐서 처리량도 FP32 누적 약 165.2, FP16 누적 약 330.3 dense로 반감 관계다. 따라서 제한 해제 주장과 방향이 맞는다.

별도 소유자의 동일 카드·동일 드라이버 비교에서는 FP16/FP32 명령 160.4→320.4, BF16/FP32 159.7→320.2 TF/s. 출력 검사 0 불일치. 그러나 이는 단일 카드의 한 쌍이며 공개 저장소의 참여자 재현이지 광범위한 독립 제3자 검증은 아니다.

04 실사용에서는

4090의 단일 카드 cuBLAS FP32 누적 GEMM은 1024³ FP16 +19%, BF16 +20%; 4096³ FP16 +34%, BF16 거의 변화 없음; 8192³ FP16 +12%, BF16 +16%였다. 같은 텐서 명령이라도 메모리 이동, 커널 선택, 전력·클록이 섞이면 성능이 달라진다. 측정 원문.

LLM 디코드는 대체로 메모리 대역폭 병목이라 효과가 작을 가능성이 높다. 긴 프리필·일부 학습·디퓨전은 계산 비중이 높아 이득 가능성이 있지만, 이 프로젝트에는 4090 FLUX/SDXL·오디오·실제 LLM 앱의 검증된 속도 수치가 없다. 선행 30 시리즈에서 보고된 프리필 개선을 4090에 그대로 대입할 수 없다.

05 우리 4090에 적용할 수 있나

판정: 지금 쓰는 Windows+WSL2 환경에서는 적용하지 않겠다. WSL2 CUDA는 Windows 호스트의 GPU를 /dev/dxg로 공유한다. WSL Linux 커널 모듈은 물리 GPU BAR0을 부팅 전에 직접 조작할 수 없으므로 Linux 저장소의 설치 경로는 해당되지 않는다. 그 경로를 검토하려면 별도 네이티브 Linux 부팅(예: 듀얼부트)·지원 PCI ID·부팅 초기 모듈·Secure Boot 상태가 모두 맞아야 한다. 이번에는 그런 실험을 하지 않았다.

HF의 Windows 쪽은 단순 커널 드라이버가 아니라 소스와 함께 배포된 UEFI 실행 파일이다. 공개 테스트 대상은 개조된 비-SUPER RTX 4080 한 장이며 특정 PCI/ROM 해시에 묶여 있다. 4090용 Windows 적용이 검증됐다는 근거는 없다. 소스 공개가 바이너리의 출처·서명·안전성을 자동 보장하지도 않는다. 따라서 우리 작업 중 FLUX/SDXL에 잠재 이득이 있어도 현 Windows 호스트에 적용할 근거가 부족하다. LLM 토큰 생성 속도 향상 목적이라면 기대값은 더 낮다. HF 설명.

06 리스크와 결론

  • 안정성: 보호된 레지스터와 펌웨어 실행 흐름을 바꾸므로 부팅·화면 복구 실패, 드라이버 갱신 시 호환성, 장시간 부하의 발열·전력·정확도는 아직 충분히 검증되지 않았다. 단기 4090 실측 최고 샘플 전력은 약 308W 양측 유사했지만 장기 안전성 증명이 아니다.
  • 보안: 일반 Linux 설치 경로에서 Secure Boot를 끄면 부팅 체인 검증이 약해진다. 복구 경로와 다른 보안 설정까지 고려해야 한다.
  • Windows 실행 파일: 공개 EFI의 저장소 목록과 크기는 확인했지만 이 분석은 로컬 다운로드·실행·서명/악성코드 분석을 하지 않았다. 배포 바이너리를 신뢰 가능한 재현 빌드로 검증하지 못했으며, UEFI 권한 코드의 위험이 크다.
  • 약관·보증: 하드웨어 비공식 동작이다. NVIDIA EULA 또는 제조사 보증에 대한 구체적 법적 효력은 여기서 확인하지 못했다.

최종 권고: 4090 수치의 핵심은 기술적으로 설득력 있고 별도 소유자 재현도 있다. 그렇지만 Windows+WSL2 실사용 4090에서는 설치 비권장. 네이티브 Linux 테스트 전용 머신을 별도로 마련하고, 앱별 이득·장기 안정성·복구 가능성을 확인할 때만 조건부 연구 대상으로 삼겠다.

따라 하다 발생한 부팅·데이터·장비 문제에 대해 이 분석은 책임지지 않는다.
