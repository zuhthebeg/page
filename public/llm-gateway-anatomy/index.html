상태를 바꾸면 미리보기가 갱신됩니다. 투입 버튼은 캡슐의 여정을 재생합니다.

설정 결과 미리보기

    Reading the machine주소는 하나.
    실행 조건은 셋.

    01

    투입구 · 단일 진입점과 인증

    공개 주소 llm.cocy.io 뒤에서 서버리스 워커가 요청을 받습니다. 인증을 먼저 확인하고 모델을 분류합니다. 여기의 인증 스위치는 허용·거부만 보여주며 자격 증명을 받지 않습니다.

    02

    뒤쪽 레일 · API 과금 경로

    워커에서 AI 게이트웨이를 거쳐 외부 API로 갑니다. 지역별 접근 제약을 다루는 중계 계층이며 모델 자체는 아닙니다. 로컬 PC가 꺼져도 이 경로는 남습니다. 사용량에 따른 API 비용과 구독 비용은 다릅니다.

    03

    가운데와 앞쪽 레일 · 구독 CLI와 로컬

    구독 CLI는 터널 뒤 PC에서 명령행 도구를 실행합니다. 로컬 경로는 PC의 서비스·모델을 사용합니다. 구독형이라고 무제한·무비용인 것은 아닙니다. 두 경로 모두 PC와 연결 상태가 필요합니다.

    04

    예비 레일 · 한 번만 허용하는 폴백

    선택 경로가 실패하면 예비 경로를 한 번 확인합니다. 이 모형의 예비 모델은 PC가 필요한 경량 구독 CLI입니다. 예비 모델도 실패하거나 PC가 꺼져 있으면 정지합니다. 자동으로 유료 API를 더 호출하지 않는, 의도된 경계입니다.

    05

    출구 · 성공과 정지는 다른 결과

    인증 거부는 분류 전, 모델 실패는 분류 후, 예비 실패는 마지막 안전장치에서 멈춥니다. 모두 같은 오류로 뭉개면 무엇을 복구해야 하는지 보이지 않습니다.

    세 번만 실험해 보세요.

    ① API 모델 + PC 꺼짐: 정상 출구가 남습니다.
    ② 구독 모델 + 선택 모델 실패: 예비 레일로 우회합니다.
    ③ 여기에 예비 모델도 실패: 안전장치에서 멈춥니다.

    구조를 이해하기 위한 단순화된 모형입니다. 모든 실제 모델·오류 정책을 재현하지 않으며, 이동 시간은 연출이지 성능 측정값이 아닙니다.
